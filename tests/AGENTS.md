# tests/: unit, fuzz, benchmark and reference tests

## Scope
doctest suites, registered in `tests/xmake.lua` and run by `xmake test` on every preset (Windows tests run under Wine in the container); fuzz targets, the headless benchmark and the reference pictures, built with them.

## Rules
- A test is small (the fewest lines that reach the code), contained (no file, network, window, clock or shared state it doesn't need; the one way a test may write a repo file is a generator case decorated `* doctest::skip()`, run by name with `--no-skip`, never in a plain run; independent of other tests), explicit (named after the behaviour, `TEST_CASE("save header rejects a truncated file")`, with literal inputs and exact expected values) and tests one behaviour. Logic only reachable through `main.cpp` or SDL moves into a `src/` function first, without changing behaviour. A sanitizer finding's test fails under that sanitizer (`--sanitizer <name>`).
- Skipped `measure ...` cases (`shipped_world_tests.cpp`) and long-run comparisons on 1 and 4 workers (the hours-of-play case, `replay_tests.cpp`'s hour of walk-tos) are run by name with `--no-skip --mode release`, write only temp files, log their tables or hashes and are never gates: no `check`, no CI.
- A unit test checks a behaviour on a handful of representative samples (about 20, each named for why it is there: first, last, a boundary, the edge case that matters), never a sweep over every item and fine time step; a loop's worst value is asserted once, not one `CHECK` per sample. Timing is profiling's (`profile`, `headless_bench`), breadth is fuzzing's.
- A hand-built host save (`tests/support/saves.hpp`) writes the game's world as its difference from the world the loading game makes (`ArenaSave`'s `data`: by default the small test data, `test::SmallData()` in `tests/support/world.hpp`, for a scene showing the world map, the built-in data otherwise), so each one generates that world once, and a game on other world data refuses it (a dev scene's scratch world likewise against the world the scene's entry build makes, built once per save); keep the shipped map (`test::ShippedData()`, 50,000 NPCs, a large part of a second to make in debug) for the cases that need its geometry or its size.
- Comments in tests follow src/AGENTS.md: a comment above a helper or test fixture that states its contract is `///` Doxygen, a comment inside a body stays only to give a why, a comment saying what a constant or data table holds stays, and none cites a spec, chunk, phase, plan, ruling, task or design doc (`lint` fails on one; a `TEST_CASE` name or `CAPTURE` string is code too).
- Layout mirrors `src/`: `tests/unit/<area>/`, one test executable per area (`<area>_tests`) to keep link times down.
- Exception: a test of process-wide state that can only be set once (logging start-up: Quill's loggers live for the whole process) gets its own executable, as in `tests/unit/log_startup/`.
- Test code passes the same lint and warnings as `src/` except MSVC C4866, C4868 and C5246 (test targets in tests/xmake.lua) and the magic-number checks (`tests/.clang-tidy`): put `TEST_CASE`s inside an anonymous namespace; literals may stand in a `CHECK` as they are.
- Each executable has exactly one `main.cpp` defining `DOCTEST_CONFIG_IMPLEMENT_WITH_MAIN` and `DOCTEST_CONFIG_IMPLEMENT` (the precompiled `unit/pch.hpp` already included doctest, so the first no longer implies the second); test files include `<doctest/doctest.h>` only.
- `unit_tests()` registers one XMake test per `*_tests.cpp` file, named after it (`game_tests/combat`), which runs only that file's cases (doctest's `--source-file`, `test_file_pattern` in tools/project_n.py, mirrored in `tests/xmake.lua`), plus `rest` for every case outside those files (`main.cpp`, a header), so `xmake test` runs each file in its own process, all at once, and drops no case. The separator before the name keeps `log_tests.cpp` apart from `sdl_log_tests.cpp`; no test file is called `rest_tests.cpp`, and two of one suite never share a name (in different folders): the selftest checks every suite.
- `unit/pch.hpp` holds every standard header the tests use: test `.cpp` files never include standard headers themselves (`lint` fails on one). Unit targets get it from `unit_tests()`. Fuzz targets and the benchmark aren't doctest suites and take the game's `src/pch.hpp` instead.
- A new area is one line in `tests/xmake.lua`: `unit_tests("<area>_tests", "unit/<area>/*.cpp", "<module>")`. The helper links the module under test (default `core`) with the modules below it and their packages, adds the precompiled header, registers the tests and runs Windows builds under Wine on Linux.
- `tests/bench/headless.cpp` is the headless benchmark (`headless_bench`, design doc 0002 §16): it ticks the stress arena and lets months pass for its world NPCs without a window, and fails over phase 4's gates on 2 workers (combat tick 8 ms, month step 0.5 s). Built with the tests but not registered as one (run on request, optimised), and takes the game's precompiled header (it isn't a doctest suite).
- `tests/reference/` compares pictures of fixed scenes with the committed PNGs beside it (design doc 0002 §8.9): `reference_tests`, built with the tests but not registered as one, as it needs a GPU. `project_n reference` runs it on Mesa's software Vulkan (Pixi's `lavapipe` environment) with SDL's offscreen video driver, so it needs no display and draws the same on every machine. Each test case runs in its own process, all at once, so a case never relies on another having run before it. It also measures game text on its captures: a label's ink at sub-pixel camera offsets (shimmer) and while it follows a moving creature (jitter), over the bare backdrop and over a flat pale ground (where the dark outline is most of the ink), so only the text's own pixels count, summing darkness signed; the glows' drives, each demo glow drawn alone and its amount (each pixel's change as a fraction of the most its colour can make there, summed) checked against `core::GlowStrength()` from tick to tick, across the 32-bit tick wrap and under reduce flashing; and the seals' shimmer, a screen-wide seal at the smallest zoom captured a quarter pixel apart, its ink compared tile by tile (Gaussian windows that move with the content, so only crawling lines change a tile's ink; tiles whose window the picture's edge cuts are left out), over the backdrop and the pale ground; and the world's shimmer, its tiles and travellers over the busiest region measured the same way, which prints `world shimmer: <value>` (a doctest `MESSAGE`, in every run's output) for `measure` to read: a regression guard only, as the tiles' hard edges shimmer above the 0.02 labels and seals hold until the backlog's world map look blends between kinds; and the fog's clouds' (the fog they and the shade add over the same unexplored land fogless, at the smallest zoom, the clouds at rest on a frame clock of 0), which prints `cloud shimmer: <value>` the same way. Every case's renderer draws seals in `seals.yaml`'s looks (a scene's portal among them); the world's cases' renderers also name NPCs from `names.yaml` (`test::ShippedNames`, which `test::ShippedData` carries too, so the world's travellers are labelled as in the game), the only cases that draw names, as composing every name's glyphs ahead takes a second or two. The world's pictures are drawn as in the game (`View::asInGame`: published at their tick and culled to the view `app::CullArea` gives), that view explored (`View::exploreAll`) and the debug sight on (`View::debugSight`), so every place and traveller in it shows whatever the cultivator has seen (the shimmer guard does the same), as the fallback view round the start misses the busiest region; they show the busiest region at three zooms, the start and portal at the largest, and the places: the capital's name, roads, river and bridge (`world_places`) and, at the smallest zoom, the capital's name under the cultivator, where its label is too small to read (`world_places_widest`), and a click's route (`world_route`: `View::walkTo` sends a `WalkTo` on the first tick; the cultivator on the road east of the capital part of the way to a tile 8 tiles east of it, its dots and end marker over the tiles, with the travellers on the roads). Every world picture also feeds an `app::FogFade` from its snapshot (snapped, as on entering the scene) into `gfx::View::fog`, with `frameClock` 0; the fog's own pictures (`View::exploreAll` and `debugSight` unset, a new game's start): `fog_start_close`, `fog_start_step`, `fog_start_middle` and `fog_start_widest` (zoom 1, 0.71, 0.4 and 0.25: the sight's diamond, the shaded edge and walkers fading at it, and the clouds' levels, two at once at 0.71), `fog_explored_path` (a route 4 tiles east and back, `View::walks`: land explored but out of sight drained, misted at sight's far edge) and `fog_uncovering` (`View::fogEased`: the fog eased a tick at a time, drawn 15 ticks, a quarter second, after a step explored a new row, with the route's dots under the clouds and `View::cursorOnTarget`'s target tile over them). A change to shaders, sprites or a scene's layout that moves pixels needs `reference --update`, a look at the new pictures (`build/reference/` holds the failing run's), and the PNGs in the same commit.
- A reference test never hangs: every wait or search loop in the suite has a bound that fails loudly, naming what never happened (`SCENE_LOAD_LIMIT_NS` for a scene's sprites, `MOST_TICKS_AFTER_CAST` for a capture tick); whole cases are bounded too (`REFERENCE_CASE_TIMEOUT` in tools/project_n.py), and each takes its worker count from `PROJECT_N_REFERENCE_WORKERS` (the game's default, `core::Jobs::DefaultWorkers()`, when unset).
- Fuzz targets: `tests/fuzz/<name>.cpp` defines `LLVMFuzzerTestOneInput`, with at least one seed in `tests/fuzz/corpus/<name>/`: one per reader of untrusted bytes (`replay`, `save`, `yaml`: the data module's readers; its seeds are the shipped `creatures`, `abilities`, `effects`, `seals`, `strings`, `names` and `manifest` files, a settings file, a seals table past a cap (`seals_caps`), a small world map (`world`), a small look for it (`world_look`) and a `%TAG` directive with eight parameters (`directive_params`: yaml-cpp's tokens grow past their first capacities); the seals and the look are read against the shipped manifest, the map against a table of its seed's place names, the look against the `world` seed's map, built once). They build only for linux-clang with AddressSanitizer (where our own code is built with `-fsanitize=fuzzer-no-link`, so coverage guides the fuzzer through it), and each replays its seeds as a test, so `check --sanitizers` covers them. A seed in an old format still runs, but only exercises the refusal: regenerate it when a format bumps. Commit every input that found a bug as a seed. The `save` target loads every input into one game, the arena on the small test map with the shipped travel rules (`test::TravellingSmallData()`), which starts each input from its own first save loaded again; each of its seeds comes from a skipped-by-default case in `unit/game/save_exactness_tests.cpp`, written by `pixi run project_n test --target game_tests -- --test-case='write the <name> save seed' --no-skip`: `fight` (the arena mid-fight: a volley, a flash, afflictions, a fox dying and one easing in, a dash), `world` (the world scene with two NPCs and one relationship between them, the edge layout), `delta` (the world scene a month on: base journeys ended, new ones by their plans) and `scratch` (the arena entered from a world a month on, mid-volley: both worlds' sections); "the save fuzz target's seeds load in its game" checks each loads; regenerate all four whenever the save layout changes.
- Coverage counts `src/` only, from the tests (linux-gcc's gcov data, reported by gcovr).
- Sanitizers run on request, never in plain `check`. Supported per preset: `SANITIZERS` in tools/project_n.py (GCC/Clang: address, undefined, thread, leak; MSVC: address). Any finding fails the run.
- The gate runs the reference cases as a release build only, never under a sanitizer (not in `check --sanitizers`, not in CI): under ThreadSanitizer every drawing case reports races inside lavapipe and LLVM, between threads lavapipe starts, none in our code, and the library-wide suppressions a gate would need also hide a race of ours that surfaces inside Mesa (2026-11-18). Our threading runs under TSan in the unit tests; a by-hand TSan run of the reference cases is worth repeating once the renderer shares memory between threads on the CPU side.

## Commands
- `pixi run project_n test --mode release --target headless_bench`: tick, publish and month-step times of the stress arena; exits 1 over a phase 4 gate
- `pixi run project_n test --preset linux-clang --sanitizer address` (also `run --sanitizer ...` for the game)
- `pixi run project_n reference` · `pixi run project_n reference --update`: take this run's pictures as the references
- `pixi run project_n fuzz <name> [--time 60]`: new inputs and crash files land in `build/fuzz/<name>/`
- `pixi run project_n test --preset linux-clang --sanitizer address --suite fuzz_<name>`: replays one fuzz target's seeds once (`-runs=0`); any other preset or sanitizer is refused with this command
- `pixi run project_n test --suite app_tests [--test data_watch]`: one test target (`--target` is the same), its files' tests in parallel; a name that is no suite, fuzz suite or test program (`headless_bench`, `reference_tests`) is refused, so a run never passes having tested nothing; `--test` (or doctest arguments) runs the binary once instead and keeps the cases of the test file it names, else the cases with it in their name
- `pixi run project_n test --mode release --target game_tests -- --test-case="the world ticked through an hour of walk-tos is the same on 1 and 4 workers" --no-skip`: a skipped long run or measurement by name (likewise `"measure the shipped world's saves over hours of play"`); double quotes, as names hold apostrophes
- `pixi run project_n test --preset linux-clang` · one target with doctest arguments:
  `pixi run project_n test --preset linux-clang --target core_tests -- --test-case='*expected*'`

## Gotchas
- `xmake test` runs a Windows `.exe` directly on Linux; it only worked on a dev machine whose kernel hands `.exe` files to Wine (binfmt_misc). The test targets call Wine themselves (`test_under_wine`), keeping its output as XMake keeps a native test's, so a parallel run prints only the failing files' output.
- MSVC sanitizer builds compile and link in the container, but only *run* on native Windows: MSVC's ASan can't hot-patch Wine's system DLLs.
- Sanitizer builds link the C++ runtime dynamically (static libc++abi collides with TSan) and don't instrument dependencies, but for yaml-cpp under ASan on libc++ (xmake.lua: an uninstrumented package mixed with libc++'s vector marks reports false container overflows; design doc 0001 §17). Because MSVC's dependencies all stay uninstrumented, its ASan turns off its std::string/std::vector annotations (the sanitizer rule in xmake.lua): the linker refuses to mix them with uninstrumented C++ packages (LNK2038 'annotate_string').
- A test that opens a window but draws nothing uses SDL's `dummy` video driver, not `offscreen`: on macOS SDL gives a new window OpenGL whenever its driver has it, and offscreen's comes through EGL, which macOS lacks ("Could not initialize OpenGL / GLES library"; `platform/window_tests.cpp`). It also turns off SDL's gamepad backends: macOS's GameController and IOKit leak under LeakSanitizer.
- A reference bound to a member of a returned temporary dangles (`const core::VolleyShape& swords = game::BuiltInData().abilities...`): linux-clang's build happened to read the right numbers, while linux-gcc's release read garbage and ticked towards tick 2.9 billion, hanging `check`. Copy the value out. Likewise `test::TestManifest()->Sprite(...)` bound to a `const&`: the temporary `shared_ptr` held the manifest's last reference, so only ASan (CI's address jobs) saw the read after free; hold the manifest in a named `shared_ptr` first.
- `reference --update` rewriting pictures your change didn't touch: they had drifted, not changed between runs (lavapipe draws every case the same to the byte, run after run, at any thread count, from GCC and Clang). A change that moves pixels only within `TOLERANCE` passes, so nobody refreshed its pictures (a passing `reference` now names them: "within tolerance but changed"): renderer changes and atlas re-packs did (among them "give the atlas an explicit 32-texel gutter" and "placeholder runes, flourishes and emblems for seals", which left `cells`, `cells_far`, `painted` and `fox_dissolving` stale until the faster-CI branch refreshed them). Reverting such a picture by hand keeps it stale for every later update: look at it and commit it with the change that moved it.
- Appending a sprite to `art/sprites.toml` moves no other (`pack_atlas` places sprites in list order); a resized or reordered sprite still shifts its pixels a few levels at zoom 1 and 2 (its exact position), though not its mips (`ATLAS_ALIGN`): look at such pictures and commit them with the change that moved them.
- MSVC C4464 (only in windows-msvc builds): an include path with `..` in it. Shared test headers live in `tests/support/`, reached as `support/<name>.hpp` through the include directory a target adds (`with_manifest()` in tests/xmake.lua); only the fuzz targets, which never build with MSVC and are missing from the compile database lint reads, include them relatively.
