# tests/: unit, fuzz, benchmark and reference tests

## Scope
doctest suites, registered in `tests/xmake.lua` and run by `xmake test` on every preset (Windows tests run under Wine in the container); fuzz targets, the headless benchmark and the reference pictures, built with them.

## Rules
- A test is small (the fewest lines that reach the code), contained (no file, network, window, clock or shared state it doesn't need; the one way a test may write a repo file is a generator case decorated `* doctest::skip()`, run by name with `--no-skip`, never in a plain run; independent of other tests), explicit (named after the behaviour, `TEST_CASE("save header rejects a truncated file")`, with literal inputs and exact expected values) and tests one behaviour. Logic only reachable through `main.cpp` or SDL moves into a `src/` function first, without changing behaviour. A sanitizer finding's test fails under that sanitizer (`--sanitizer <name>`).
- A unit test checks a behaviour on a handful of representative samples (about 20, each named for why it is there: first, last, a boundary, the edge case that matters), never a sweep over every item and fine time step; a loop's worst value is asserted once, not one `CHECK` per sample. Timing is profiling's (`profile`, `headless_bench`), breadth is fuzzing's.
- Layout mirrors `src/`: `tests/unit/<area>/`, one test executable per area (`<area>_tests`) to keep link times down.
- Exception: a test of process-wide state that can only be set once (logging start-up: Quill's loggers live for the whole process) gets its own executable, as in `tests/unit/log_startup/`.
- Test code passes the same lint as `src/` (no test exemptions): put `TEST_CASE`s inside an anonymous namespace and name test values as `constexpr` constants.
- Each executable has exactly one `main.cpp` defining `DOCTEST_CONFIG_IMPLEMENT_WITH_MAIN` and `DOCTEST_CONFIG_IMPLEMENT` (the precompiled `unit/pch.hpp` already included doctest, so the first no longer implies the second); test files include `<doctest/doctest.h>` only.
- `unit/pch.hpp` holds every standard header the tests use: test `.cpp` files never include standard headers themselves (`lint` fails on one). Unit targets get it from `unit_tests()`. Fuzz targets and the benchmark aren't doctest suites and take the game's `src/pch.hpp` instead.
- A new area is one line in `tests/xmake.lua`: `unit_tests("<area>_tests", "unit/<area>/*.cpp", "<module>")`. The helper links the module under test (default `core`) with the modules below it and their packages, adds the precompiled header, registers the test and runs Windows builds under Wine on Linux.
- `tests/bench/headless.cpp` is the headless benchmark (`headless_bench`, design doc 0002 §16): it ticks the stress arena and lets months pass for its world NPCs without a window, and fails over phase 4's gates on 2 workers (combat tick 8 ms, month step 0.5 s). Built with the tests but not registered as one (run on request, optimised), and takes the game's precompiled header (it isn't a doctest suite).
- `tests/reference/` compares pictures of fixed scenes with the committed PNGs beside it (design doc 0002 §8.9): `reference_tests`, built with the tests but not registered as one, as it needs a GPU. `project_n reference` runs it on Mesa's software Vulkan (Pixi's `lavapipe` environment) with SDL's offscreen video driver, so it needs no display and draws the same on every machine. Each test case runs in its own process, all at once, so a case never relies on another having run before it. It also measures game text on its captures: a label's ink at sub-pixel camera offsets (shimmer) and while it follows a moving creature (jitter), over the bare backdrop and over a flat pale ground (where the dark outline is most of the ink), so only the text's own pixels count, summing darkness signed; the glows' drives, each demo glow drawn alone and its amount (each pixel's change as a fraction of the most its colour can make there, summed) checked against `core::GlowStrength()` from tick to tick, across the 32-bit tick wrap and under reduce flashing; and the seals' shimmer, a screen-wide seal at the smallest zoom captured a quarter pixel apart, its ink compared tile by tile (Gaussian windows that move with the content, so only crawling lines change a tile's ink), over the backdrop and the pale ground. A change to shaders, sprites or a scene's layout that moves pixels needs `reference --update`, a look at the new pictures (`build/reference/` holds the failing run's), and the PNGs in the same commit.
- A reference test never hangs: every wait or search loop in the suite has a bound that fails loudly, naming what never happened (`SCENE_LOAD_LIMIT_NS` for a scene's sprites, `MOST_TICKS_AFTER_CAST` for a capture tick).
- Fuzz targets: `tests/fuzz/<name>.cpp` defines `LLVMFuzzerTestOneInput`, with at least one seed in `tests/fuzz/corpus/<name>/`: one per reader of untrusted bytes (`replay`, `save`, `yaml`: the data module's readers; its seeds are the shipped `creatures`, `abilities`, `effects`, `seals`, `strings` and `manifest` files, a settings file and a seals table past a cap (`seals_caps`); the seals are read against the shipped manifest). They build only for linux-clang with AddressSanitizer (where our own code is built with `-fsanitize=fuzzer-no-link`, so coverage guides the fuzzer through it), and each replays its seeds as a test, so `check --sanitizers` covers them. A seed in an old format still runs, but only exercises the refusal: regenerate it when a format bumps. Commit every input that found a bug as a seed. The `save` fight seed (`corpus/save/fight`: the arena mid-fight, without its world tier) is generated by the game tests' skipped-by-default case "write the fight save seed": `pixi run project_n test --target game_tests -- --test-case='write the fight save seed' --no-skip` writes it (its "the mid-fight save loads" case checks the same save loads); regenerate it whenever the save layout changes.
- Coverage counts `src/` only, from the tests (linux-gcc's gcov data, reported by gcovr).
- Sanitizers run on request, never in plain `check`. Supported per preset: `SANITIZERS` in tools/project_n.py (GCC/Clang: address, undefined, thread, leak; MSVC: address). Any finding fails the run.

## Commands
- `pixi run project_n test --mode release --target headless_bench`: tick, publish and month-step times of the stress arena; exits 1 over a phase 4 gate
- `pixi run project_n test --preset linux-clang --sanitizer address` (also `run --sanitizer ...` for the game)
- `pixi run project_n reference` · `pixi run project_n reference --update`: take this run's pictures as the references
- `pixi run project_n fuzz <name> [--time 60]`: new inputs and crash files land in `build/fuzz/<name>/`
- `pixi run project_n test --suite app_tests [--test data_watch]`: one test target (`--target` is the same); `--test` keeps the cases of the test file it names, else the cases with it in their name
- `pixi run project_n test --preset linux-clang` · one target with doctest arguments:
  `pixi run project_n test --preset linux-clang --target core_tests -- --test-case='*expected*'`

## Gotchas
- `xmake test` runs a Windows `.exe` directly on Linux; it only worked on a dev machine whose kernel hands `.exe` files to Wine (binfmt_misc). The test targets call Wine themselves (`test_under_wine`).
- MSVC sanitizer builds compile and link in the container, but only *run* on native Windows: MSVC's ASan can't hot-patch Wine's system DLLs.
- Sanitizer builds link the C++ runtime dynamically (static libc++abi collides with TSan) and don't instrument dependencies. MSVC's ASan therefore turns off its std::string/std::vector annotations (the sanitizer rule in xmake.lua): the linker refuses to mix them with uninstrumented C++ packages (LNK2038 'annotate_string').
- A test that opens a window but draws nothing uses SDL's `dummy` video driver, not `offscreen`: on macOS SDL gives a new window OpenGL whenever its driver has it, and offscreen's comes through EGL, which macOS lacks ("Could not initialize OpenGL / GLES library"; `platform/window_tests.cpp`). It also turns off SDL's gamepad backends: macOS's GameController and IOKit leak under LeakSanitizer.
- MSVC C4866 (shown only by `check`'s windows-msvc build): a temporary with a destructor inside `CHECK` (a `std::string`, a returned `std::expected`, a vector passed where a span is expected). Name the value first.
- A reference bound to a member of a returned temporary dangles (`const core::VolleyShape& swords = game::BuiltInData().abilities...`): linux-clang's build happened to read the right numbers, while linux-gcc's release read garbage and ticked towards tick 2.9 billion, hanging `check`. Copy the value out.
- MSVC C4866 also fires on argument temporaries that have no destructor (a `std::optional<core::Vec2>` made from a `Vec2`, a span from an array) inside `CHECK`: name the call's result first.
- MSVC C4464 (only in `check`): an include path with `..` in it. Shared test headers live in `tests/support/`, reached as `support/<name>.hpp` through the include directory a target adds (`with_manifest()` in tests/xmake.lua); only the fuzz targets, which never build with MSVC and are missing from the compile database lint reads, include them relatively.
