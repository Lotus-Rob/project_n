# src/: game and engine

## Scope
All game and engine code, laid out by docs/design/0002-engine-architecture.md (§4 modules, §16 phases): XMake static libraries in `src/<module>/`, each linking only the modules below it (`MODULES` in tools/project_n.py; `lint` checks the includes).
Modules: `core` (frame contract, value types), `data` (reads the YAML; only it sees yaml-cpp), `platform`, `gfx`, `game` (links only `core`), `app` (puts the program together); each `module.dox` says what it holds. `main.cpp` reads the files and runs an `App`.
The YAML files, which are hashed game data, which presentation, and the C++ each is read into → `assets/AGENTS.md`. A new system is owned by `App` or `Game`, never passed in as loose arguments → `app/app.hpp`.

## Rules
- C++23 with conventional headers (no modules). Every translation unit's includes lead to `core/cxx23.hpp`, which fails the build below C++23; include it with `// IWYU pragma: keep` (it declares nothing).
- Include order: project headers, then library headers (`<SDL3/...>`), then (headers only) the standard library, as blank-line-separated blocks. clang-format sorts within a block but doesn't regroup.
- Formatting and lint come from the pinned tools: `pixi run project_n fmt` and `pixi run project_n lint` (warnings are errors).
- Headers include only the standard library and our own headers. Third-party and platform code (SDL, Tracy, `<windows.h>`) stays in `.cpp` files behind our own types (a pimpl or an opaque handle); a header doesn't forward-declare its types either. `lint` fails on a third-party include in a header; only a facade (`FACADES` in tools/project_n.py) includes its own library, and a module's private `src/<module>/internal/` headers its libraries (nothing outside the module includes them).
- Numbers use the sized types from `core/types.hpp`: `i8`–`i64`, `u8`–`u64`, `f32`, `f64`, never `int`, `unsigned`, `long`, `float`, `double` or `std::uint32_t`-style names (`int main(int, char**)` excepted; `std::size_t` stays for sizes and indices; `lint` fails on the others). `pch.hpp` includes it; headers include it themselves.
- `pch.hpp` is the game's precompiled header and holds every standard header the sources use: a `.cpp` never includes a standard header itself (`lint` fails on one); add it to `pch.hpp`. Headers still include everything they use. It is a header too: no third-party ones.
- Logging: extensive, through `core/log.hpp` (Quill; `std::format` syntax, written on a background thread). Log outcomes (what was chosen, what happened, what failed and why), never code steps or internals, and never every frame (profile instead). `main` calls `core::log::Start(directory)` first; logs go to the console (Info and up) and to a rotating `project_n.log` in the per-user data folder. Nothing else writes output (`std::print`, iostreams, `printf`, `SDL_Log`) and nothing else includes Quill or Tracy: `lint` fails on them. Levels:
  - `PN_LOG_DEBUG` detail for diagnosing (decisions, state changes, values; log file only)
  - `PN_LOG_INFO` progress in a normal run (subsystems starting and stopping, what was chosen)
  - `PN_LOG_NOTICE` significant normal events (start, stop)
  - `PN_LOG_WARNING` unexpected but recovered · `PN_LOG_ERROR` a failure and its cause · `PN_LOG_CRITICAL` a failure the program can't continue after
- Profiling: `PN_PROFILE_ZONE();` at the top of every function that runs each frame (except per-item functions: Gotchas), `PN_PROFILE_FRAME();` once per frame, from `core/profile.hpp` (Tracy). They collect only in `releasedbg` and do nothing elsewhere: `./dev profile [--seconds N] [-- --stress]` records a run into `build/profiles/` (the game quits by itself with `--quit-after N`, so no click into the viewer takes its focus and pauses it), `./dev profiler <file>` opens it; or live, `./dev run --mode releasedbg` and `./dev profiler`.
- Every header starts with a `/// @file` comment followed by `/// @ingroup <module>` (the group is in `src/<module>/module.dox`), and every public class, function, member, variable and enum it declares has a Doxygen comment (`///`): what it does and promises, not how. `lint` fails on a missing or broken one.
- Errors: an expected failure returns `std::expected<T, core::Error>` (`core/error.hpp`); a broken invariant is `PN_ASSERT(condition, message)` (`core/assert.hpp`: on in debug and releasedbg). Our code throws nothing.
- Entities: EnTT only through `core/ecs.hpp` (a facade; `core::Domain`, `core::Registry`). Anything that crosses a domain, a tick, a save or input names an entity by its `core::StableId`, never an EnTT handle; `core::State::Create` takes it from one of two ranges, both counters saved and never reused: the world's (`core::IdRange::World`, NPCs and groups, from 1, so a world generated from a seed numbers alike whatever ran before) and a scene's own (`IdRange::Scene`, from `core::SCENE_ID_BASE`, 2^62: the cultivator, creatures, a scene's props; one counter for the session, carried from scene to scene whichever world runs); structural changes (create, destroy) never happen inside a job chunk.
- Simulation code (`core`, `game`) is deterministic within one binary (design doc 0002 §7.4): transcendental maths through `core/math.hpp` (`lint` fails on `std::sin` and the like there), random numbers through `core/random.hpp` keyed on the state counter, never `std::*_distribution`, never a clock.
- Comments in `.cpp` files only explain why, or a complexity the code can't show; never restate what the code does. A comment directly above a function, method, lambda-holding variable or helper type that states its contract (what it returns or does, its inputs' ranges, its promises) is `///` Doxygen; one that only restates the body goes; a comment saying what a constant or data table holds is that constant's documentation and stays. No comment cites a spec, chunk, phase, plan, ruling, task or design doc (`lint` fails on one): say why in your own words.
- Rendering: the world pass first draws the world map when the snapshot shows it (`Snapshot::worldMap`, from `SceneTraits::worldMap`: only the world scene; the scene publishes no tiles and no painted ground; first its painted ground, one quad over the map's part of the view (`gfx::GroundQuad`; nothing past the map, none when the view misses it) by `internal::GroundRenderer` (`gfx/internal/features/ground.hpp`: the ground field of `gfx/ground_field.hpp` as a two-byte texel per tile, point-sampled for the kind and linearly for the shore, rebuilt only when `SetWorld` is called, and `gfx::GroundUniformsOf`'s uniforms from `gfx/ground.hpp` (made again only then too, the zoom set each frame): paper, washes bled across noisy edges, water deepening from an inked shore, the faint grid faded by zoom, every noise octave and line faded before it gets finer than a couple of pixels; a veil mode, a cloud-shade mode and a paper-only mode too, the paper drawn alone, without the rivers, roads, terrain sprites or veil, when `View::terrainParts` asks: `gfx::TerrainParts`, which only the shimmer measure sets, `AllButRoads` leaving out the road ribbons), then the rivers on it (an `internal::LineRibbonRenderer`, `gfx/internal/features/line_ribbons.hpp`: `gfx::DrawRivers`' bands built once per map and look, premultiplied over; a river's end is drawn on to where its last stretch meets another river's middle (not within a tile of that river's own end, where the other flows into it), or a tile on into the water ahead of it, fading out, the map's waypoints untouched; its start narrows from a point at a spring (the look's `taper`), fades in a tile out of a pond's water and is left as laid at a branch), then the roads over them (a second `LineRibbonRenderer`: `gfx::DrawRoads`' bands along `core::RoadCurves`, which `SetWorld` works out once, in `gfx::RibbonShapeOf`'s shape from `world_look.yaml`'s `road:`), all shaded by the fog as land is through `shaders/fog.hlsli` (`FoggedLand`, shared with the sprite shader), then over them the terrain's sprites: `gfx/terrain_draw.hpp` (`DrawTerrain`) lays out, for the tiles in view at the camera's zoom, the bridges (across or down by the road curve's heading nearest the tile: across when it runs at least as much east to west) and fords (the leading batch), the stamps and place paintings sorted by foot and the mist puffs (`gfx/stamp_draw.hpp`, `DrawStamps`: fixed by a hash of each tile, `gfx/tile_hash.hpp`, laid out past the view by their reach, small ones fading by rank below their kind's zoom), and last the place markers (`TerrainDrawing::markersFrom`), no tiles and no river or road overlays, from the `core::WorldMap` and `core::WorldLook` given to `Renderer::SetWorld`, which App calls at start and whenever a look reload replaces the look; one more sprite buffer, laid out and copied again only when the view reaches other tiles, the zoom changes or SetWorld is called; the renderer draws its batches before `markersFrom`, then the ground pipeline again in its veil mode (pale patches over everything so far), then the markers; every instance but the markers flagged `core::INSTANCE_FOGGED_LAND`, which the sprite shader drains to sepia and veils in mist where its pixel's tile is explored but out of sight and shades in the look's shade colour where it is unexplored, the markers `core::INSTANCE_FOG_SHADE` (`FogShaded`: only the shade, so a place found once stays in colour but hides under the clouds), by `View::fog` (`gfx::FogFrame`, `gfx/fog.hpp`) through `internal::FogTexture` (`gfx/internal/features/sprites.hpp`: a two-channel UNORM texture a texel per tile, explored and in sight, filtered linearly and clamped, uploaded only when its revision changes, bound to every sprite draw; with no fog a 1 × 1 one and nothing shaded), as an instance flagged `core::INSTANCE_SIGHT_FADE` fades with sight at its `core::SightPoint` and a label by `gfx::FogOpacity` (a walker's name also by `gfx::ExploredFade` at its foot, as far as the shade under the clouds leaves it uncovered), one wholly hidden taking no label room), then the player's route (`gfx/route_draw.hpp`, another sprite buffer laid out each frame from `Snapshot::route`: a `route_dot` every `route.spacing` units of `world_look.yaml`, `route_marker` on the end), then draws the snapshot's ground and decals (its first `Snapshot::groundBatches`, which the draw list cuts there), the ground seals (each its ink wash and its particles' ink, with the light shadows overhead seals cast on the ground, normal blend, then its lines and its light's pillars, sparks and shards, additive), the rest of the snapshot's sprites, the selection and hover outlines (the glows `selected` and `hover`, drawn alone round those sprites), the ground pipeline once more in its cloud-shade mode while the view has fog (the look's shade colour, opaque where land is unexplored and gone from half explored on, the land's own shade edge, so nothing standing on unexplored land shows through the clouds' gaps: only the debug sight draws walkers there), the fog's clouds (`gfx/cloud_draw.hpp`: `DrawClouds` lays them out each frame for the view, zoom and `View::frameClock` into one sprite buffer of `MAX_CLOUD_INSTANCES`, one normal batch, only when `View::fog` has columns) and over them the target cursor's tile (`gfx::DrawTargetTile`, its own one-instance buffer from `Renderer::SetTargetTile`: `target_tile`), then the upright and overhead seals (drawn alike, their light with them, capped in opacity, under all that follows, so the swords fly out over them and health bars, numbers and the HUD stay readable; `gfx/seal_draw.hpp` lays every seal out at the render time from `Snapshot::seals`, `gfx/internal/features/seals.hpp` draws them), the swords' trails (additive ribbons), the overlay (sprites the main thread places each frame at the render time: the swords, each one instance wearing its glow, then the poison lance's additive bursts, then the health bars, which follow their creature's label and stay readable over the swords; `gfx/volley_draw.hpp`: the snapshot carries each volley as one record, `Snapshot::volleys` with their targets in `volleyTargets`, never a sword each, and every sword is placed by `core::SwordAt` at the exact render time), then text, then the HUD in target pixels (`app/hud.hpp` lays it out: its bars through the overlay's sprites, then its lines); on the world map it also lays out the date line (`Hud::BuildDate` from `Snapshot::calendar`: month and day counted from 1, "Paused" after it while the world is paused, right-aligned top right through `HudLine::alignRight`), whose box (`Hud::DateLineArea`, laid out by `hud.date_inset` in `effects.yaml`, as wide as the text draws, `gfx::Renderer::HudLineWidth`, and never narrower than `hud.date_width`) is the HUD's one clickable area: a primary mouse press in it sends `ToggleWorldPause` through `app::DateLineClick` and nothing else, ahead of the world's click). Nothing outside `gfx` calls SDL_GPU. Shaders are HLSL in `shaders/<name>.<stage>.hlsl`; after changing one, `./dev shaders` (Linux or Windows) and commit `shaders/bin/` and `src/gfx/generated/` with it (`lint` fails on stale binaries). `gfx` reaches them through the generated `gfx/generated/shaders.hpp`.
- Third-party code comes from xmake-repo packages with exact versions; nothing is vendored into `src/`.
- `src/<module>/generated/` holds headers that `shaders` and `atlas` write (shader binaries, the sprite names; the atlas manifest itself is `assets/manifest.yaml`, which `main` loads into `core::Manifest`): never edit them by hand; `fmt` and `lint` skip them, and `lint` fails when they are stale.
- The arena (`game/scenes/arena.hpp`) is the growing demo scene: a new game or engine feature shows up in it, in the same branch, and joins the header's list.
- Scenes are stateless classes in `game/scenes/` behind `game/scene.hpp`, listed in `game/scenes.cpp` in F2's order (a scene's key is its place there) → `game/scenes.hpp`.
- The host owns all state and never checks which scene it runs: the game's world outlives scene changes, a dev scene runs on a scratch world made afresh → `game/host.hpp`, `game/world_state.hpp`.
- Saves hold the game's world as its difference from its base (identity: seed, `GENERATOR_VERSION`, `BaseHash`), then a scratch world, then the scene; a save never sorts, a load restores each storage's order → `Host::Save` in `game/host.hpp`.
- A change to what `GenerateWorld` makes raises `GENERATOR_VERSION` → `game/world_state.hpp`.
- Presentation-only host state (walk tables, kept walks, the player's walk, the drawn shift, `FogVersion`, the debug sight) is never saved, hashed or read by the simulation → `game/host.hpp`.
- Travel, journeys and month steps: every random draw is keyed on the seed, state counter, month and NPC, so a run is the same on any worker count → `game/travel.hpp`.
- The world map's walking and fog live in `core/journey.hpp`, `core/leg_walk_cache.hpp`, `core/road_curve.hpp`, `core/fog.hpp` and `core/calendar.hpp`; the world scene is `game/scenes/world.hpp`.
- A new module adds its directory's `module.dox`, an XMake target with `add_deps` on the modules below it, and its commit scope to `SCOPES` in tools/project_n.py.

## Commands
- `./dev run [--debug] [-- --stress | --painted | --cells | --world]` (native preset; `--preset` picks another; `--stress`: the stress arena, about 100,000 instances; `--painted`: the still painted test scene; `--cells`: a map cell grid, to judge the mips as the view zooms; `--world`: the world map, 20 screens across, its painted terrain and the travellers between its cities (`game/scenes/world.hpp`); `--<name>` for each scene in `art/scenes.toml` the game knows; `--quit-after SECONDS`: quit by itself; `--zoom VALUE`: every scene starts at this zoom, from 0.25 (the farthest) to 2 (the closest), for `profile -- --cast-swords --zoom 2`; `--burst`: F7's burst once a second, for `profile -- --burst`; `--debug-sight`: every tile of the world map in sight from the start, unexplored land staying under cloud (F3 flips it; the switch snaps the fade, explored tiles still ease in as they are explored, and the host's sight and explored tiles are untouched); `--cast-swords`: the flying swords beside the player 4 seconds after the last cast or as soon after as they are ready (about every 6 seconds), the fire bolt topping the Qi up first, for `profile -- --cast-swords`, with each cast's latency to its first drawn sword in the log file at debug level; `--workers N`: pin the job system to N workers, 1 to 64; `--unpaced`: present immediate before mailbox, so the display's rate doesn't cap a measurement; `--camera-path` (for `--world`): 2 seconds after the scene runs, the camera follows a fixed path (`app/camera_path.hpp`, which `app::CameraControl` moves by: follow the cultivator walking east by a scripted Move in steps of 0.5 s (standing 0.1 s, then walking 0.4 s: eight presses, each from a standing cultivator), pan 3 screens, zoom in to 2 and out to 0.25, the widest view over the busiest region, zoom 0.6 with labels) and the game quits after it, logging `camera path: <segment>` at each segment's start (also a Tracy message) and `input latency: <ms> ms from a Move press to its first drawn frame` for each press; `--travel-share PER_MILLE`: the world map's travel share (`world.yaml`'s `share_per_mille`) set to this, 0 to 1,000, before the game starts (`game::SetTravelShare`, so the data's hash follows it), for `measure`'s world run; `--month-step-at SECONDS` (with `--camera-path`): one month passes (`core::ActionKind::AdvanceCalendar`, as M sends it) at that second of the path, logging `camera path: month step` (also a Tracy message; `app::PathMonthStep`, `app::MonthStepAtOf`), for `measure`'s world run; `--fullscreen`: this run fullscreen at the display's native size, whatever `settings.yaml` says; the log names the display mode as `display: WxH at N Hz (name)`, again whenever the window lands on another display or its mode changes (a compositor may place a new window elsewhere than SDL opened it)). In the game (default bindings, `app/bindings.cpp`): WASD, the arrows, the d-pad or the left stick walk the cultivator (pan the still scenes; walking onto a scene's glowing portal goes to the next walkable scene: arena, stress, world, then the arena again), in the arena a left click casts the generator, a right click the spender, Space the movement and 1 to 5 the specials and ultimate (Alt and a left click selects; elsewhere a left click selects, except that on `world` one on open ground walks the cultivator there and lets go of the selection), outside combat the camera pans (and drags) freely: I, J, K, L or the right stick pan it at one screen a second, so does the pointer within 2% of the window's edge (`edge_pan: false` in `settings.yaml` turns that off), the middle button (and the right, outside combat) drags it, and in `world` the camera follows the cultivator loosely (it moves only when the foot leaves a centred box half the view's width and height, by the overshoot), panning frees it until C, the right stick's click or a middle click that drags nothing snaps it back to the cultivator at the centre (in a still scene, back to its start; combat scenes always follow the cultivator exactly), the wheel, the shoulder buttons or `-` and `=` (by their place on the keyboard) zoom, Escape quits, P or the gamepad's Back pauses the world (the date line's click too); on `world`, T or the gamepad's Y shows the target cursor on the cultivator's tile (the same again hides it; it hides too when a click walks or selects), while it shows the movement keys, the d-pad or the left stick step it a tile at a time (held: after 0.3 s, then every 0.15 s) instead of walking the cultivator, and Enter or the gamepad's A walks there, as a click does (`app::TargetCursor`); debug keys: F2 switches to the next scene (arena, stress, painted, cells, world; the portals skip the still ones), F3 puts every tile of the world map in sight (unexplored land stays under cloud) or stops, M lets a month pass at once (the world clock jumps to the next month's first tick), F5 saves, F9 loads, F6 starts or finishes recording a replay, F10 plays or stops it, F7 hits every fox thousands of times (the damage numbers' stress), F8 hides and shows the arena's showcase seals; saves and the replay go to the per-user data folder's `saves/`. Debug builds reload `assets/data/` (the source tree's; all but `world.yaml`, `names.yaml` and `strings.yaml`, read once at start) within half a second of an edit; a broken edit is logged with its line and the old data stays

## Gotchas
- A `///` comment right after the `/// @file` block joins it, leaving the next declaration undocumented: put a blank line after the file comment.
- SDL 3 silently falls back to XWayland when the compositor lacks `fifo-v1` (niri does), even with the Wayland driver compiled in. `platform/window.cpp` hints `wayland,x11`; `SDL_VIDEO_DRIVER` still overrides it.
- A `switch` over every value of an enum fails either way under Clang's `-Weverything`: `-Wswitch-default` wants a `default`, `-Wcovered-switch-default` rejects one. Use `if`s.
- A member that a designated initialiser can omit needs an initializer under Clang (`-Wmissing-designated-field-initializers`; it names one member per site): `{}` under `// NOLINTNEXTLINE(readability-redundant-member-init): designated initializers omit it; Clang warns without one`, or a value tidy accepts (`= nullptr`, `= std::nullopt`). Every other member with a default constructor stays bare.
- MSVC's warnings don't show in native Linux builds, only in the windows-msvc builds (each task's release build, `check`): `std::array` needs double braces (C5246), also for a member default, constant or argument (`size{ 1.0F, 1.0F }`, `f({ 255, 255, 255 })`). Deduced from scalars (`std::array KEYS{ InputCode::KeyW, ... }`) it warns too, and double braces then stop the deduction (C2641): write `std::to_array({ ... })`. Arrays of aggregates (`std::array CASES{ Case{ ... }, ... }`) pass.
- `std::ranges::find` over a `std::array`: clang-tidy wants `const auto*` (libc++'s iterator is a pointer), which MSVC rejects (its iterator is a class; only windows-msvc builds show it). Search a named `std::span` of the array instead and keep `const auto`, as `platform/window.cpp` does.
- Profiling is skewed by anything else animating on the GPU: a browser page with a moving canvas (the superpowers brainstorm companion's) made the same build's frames four to eight times slower (2026-11-12). Close animated pages and leave the game's window focused while `profile` runs; compare a build only with a baseline taken the same way.
- On the development machine (niri) `settings.yaml`'s window size isn't what a profile runs at: the window is tiled (1280×720 became 1256×1368), and fullscreen is paced at the monitor's 165 Hz despite mailbox, where every zone ran three to five times slower than unthrottled (2026-11-13). Record the size `niri msg windows` shows, and compare zones only between runs paced alike.
- `PN_PROFILE_MESSAGE` takes a `std::string` or `std::string_view`, never a bare literal (it calls `.data()`). The macros are empty outside `releasedbg`, so `test` and `lint` compile a wrong call, and only `check`'s releasedbg build or `measure` fails on it: name the text as a `constexpr std::string_view`.
- A function called once per item, thousands of times a frame, takes no `PN_PROFILE_ZONE`; its caller's zone (or its job chunk's) measures it. Under a capture a zone costs its caller about 0.25 µs (measured 2026-11-11 as a parent zone's time less its children's), many times a small function's work: the damage numbers' nested zones were 2.3 of the 2.4 µs each number took to place.
- MSVC C4868 (only in windows-msvc builds): braces around constructor arguments that build a temporary with a destructor (a `std::filesystem::path` copied into a by-value parameter, a `std::move`d one). Use parentheses for such constructor calls.
- MSVC C4623 (only in windows-msvc builds): an aggregate holding a member with no default constructor (`core::State`) warns that its own default constructor is implicitly deleted. Give it a constructor (`game/host.hpp`'s `Loaded` takes every member, `game/world_state.hpp`'s `WorldState` its `core::State`).
- MSVC C4686 (only in windows-msvc builds): a function declared returning a `std::array<...>` that nothing has instantiated by then warns at its first call. Name the type (`using Table = std::array<...>`) and `static_assert(sizeof(Table) == ...)` it before the declaration (`gfx/glow_table.hpp`).
