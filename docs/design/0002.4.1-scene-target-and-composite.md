## 1. What chunk 2 builds

Today `Renderer::Impl::DrawWorld` draws the sprites straight into the swapchain texture, whose format must be sRGB
(`SDR_LINEAR`), so that blending happens on light; a window without one stops the game (`renderer.cpp`'s
`shortcut:`). Chunk 2:

- draws the **world pass into a scene target** (`R16G16B16A16_FLOAT`, §2): the ground, the world, the effects and
  both outlines, as today, only into another texture;
- adds the **final pass**: a **composite** of the scene target into the swapchain that **always encodes sRGB itself**
  (§3), so the swapchain is always plain `SDR` and the shortcut goes;
- draws `Capture` through the same two passes, so the reference pictures judge the path that ships (§4).

**Moved to their first users** (decision 1):

| The mesh path (cycled vertex buffer, static quad index buffer, `mesh` shaders) | chunk 3, with text | Text is its only user in this phase; its vertex format, textures (R8 glyph pages) and draw items are shaped by the glyph cache, so designing them apart means designing them twice. |

needs one beyond the mesh path) becomes **0002.4.2** and chunk 4's 0002.4.3; 0002.4 §1 is updated.

## 2. The scene target

- **A `SceneTarget`** (`gfx/internal/resources/scene_target.{hpp,cpp}`): one `R16G16B16A16_FLOAT` 2D texture, usage
  `COLOR_TARGET | SAMPLER`, one mip, and its width and height.
- **Sized to what it's drawn for:** each frame (and each capture) asks for a target of the swapchain texture's size
  (`Frame::width`, `height`, which SDL already returns with the texture); `internal::FitSceneTarget(device, target, width, height)`
  recreates it only when the size differs. The old texture is released at once: SDL frees it after the frames in
  flight that use it. This replaces 0002 §8.4's "recreated on `SDL_EVENT_WINDOW_PIXEL_SIZE_CHANGED`" (§8): the
  acquired size is the one that matters (it is what the frame draws into), it needs no event plumbing from `platform`,
  and the comparison is two integers a frame.
- **Render scale** stays 1.0 and isn't built: the target is the swapchain's size. It arrives with a setting.
- **The world pass** clears it to `BACKDROP` (`load_op = CLEAR`, `cycle = true`: nothing loads the old contents, 0002
  §8.7) and draws exactly what `DrawWorld` draws today. A snapshot of a scene the renderer doesn't hold still draws
  the backdrop only.
- **The sprite pipelines** are created for `R16G16B16A16_FLOAT` instead of the swapchain's format. Their blend states
  don't change: premultiplied over and additive, now at half-float precision, so additive light above 1.0 survives
  until the composite clamps it (bloom, later, will use that headroom).

## 3. The composite

- **The swapchain is always `SDL_GPU_SWAPCHAINCOMPOSITION_SDR`** (`B8G8R8A8_UNORM` or `R8G8B8A8_UNORM`, which SDL
  guarantees), never `SDR_LINEAR`, even where it is offered (decision 2). The composite **encodes sRGB in its
  shader** on every machine, so:
  - there is one path, and the reference pictures test it (an `SDR_LINEAR` path would be the one lavapipe and most
    desktops take, and the other would ship untested);
  - the UI, drawn after the composite in the same pass (chunks 4–6), blends in sRGB-encoded space everywhere, which is
    what RmlUi's colours and its own backends assume. With `SDR_LINEAR` where available, the same document would
    blend differently from machine to machine.
  - The cost is a few ALU instructions per pixel in a pass that runs anyway.
- **`Compositor`** (`gfx/internal/features/composite.{hpp,cpp}`): one pipeline for the swapchain's format, no blending,
  and a nearest-neighbour clamped sampler (target and swapchain are the same size; render scale below 1 would switch
  it to linear). `Draw(pass, scene)` binds the scene target and draws one full-screen triangle.
- **Shaders,** one file per stage: `shaders/composite.vert.hlsl` builds the triangle from `SV_VertexID` (no vertex
  buffer, no uniforms); `shaders/composite.frag.hlsl` samples the scene, clamps to [0, 1] and applies the exact
  piecewise sRGB curve (`x ≤ 0.0031308 ? 12.92x : 1.055x^(1/2.4) − 0.055`), the one the hardware's sRGB encode uses,
  with alpha 1. `./dev shaders` commits the binaries and the generated header with them.
- **The final pass** is one render pass on the swapchain texture (`load_op = DONT_CARE`: the triangle covers every
  pixel): the composite now, the UI after it from chunk 4. Without a swapchain texture (the window can't be shown),
  neither pass runs; the copy pass still does, as today.
- **`BACKDROP`** keeps its linear value; its comment says the composite encodes it rather than the swapchain.

## 4. Capture and the reference pictures

- `Capture` draws the world pass into the same scene target (fitted to the picture's size), then the composite into
  its picture texture, which keeps the swapchain's format so the composite's one pipeline serves both. The red–blue
  swap for a `B8G8R8A8` format stays, now checking `B8G8R8A8_UNORM` instead of `B8G8R8A8_UNORM_SRGB`.
- **What should change in the pictures:** each blend used to be rounded to 8-bit sRGB in the target; now blends run
  at half-float and are rounded once, in the composite. Where sprites overlap translucently a pixel can move by a
  level or two, inside the reference tests' tolerance (2 levels, 1 pixel in 10,000 past it). If a picture moves past
  it, I look at it (look-at-the-game skill), and `reference --update` only where the difference is the expected
  rounding, saying so in the commit.
- **A new check for the resize:** one reference view captures a smaller picture first and then its real one with
  the same renderer, so a target that isn't refitted fails the comparison.

## 5. Tidied on the way

- **`gfx::View`** (`gfx/camera.hpp`, beside `Camera`): `{ f64 alpha; Camera camera; std::optional<std::size_t>
  outlined; }`. `Draw(snapshot, view)` and `Capture(snapshot, view, width, height)` take it, and so do `Impl::Frame`
  and the world pass, instead of four loose arguments passed through four functions (chunk 3 would add a fifth).
  App and the reference tests build one.
- **`renderer.cpp` keeps only orchestration:** the passes' drawing lives in `features/` (sprites, composite), the
  targets in `resources/`; the frame becomes upload, world pass, final pass, submit.
- **The shortcut and its error** (`the window has no sRGB swapchain`) go, and `Renderer::Create`'s comment drops the
  sRGB caveat.

## 6. Testing

- **Reference pictures** (lavapipe, both compilers): the five existing views through the scene target and composite,
  plus the refit check of §4.
- No unit test for the sRGB curve: it lives in HLSL, and the reference pictures compare it with the hardware encode
  that made them, pixel by pixel.
- `check` on every preset (the new shaders through DXIL and MSL included), and `check --container`: the new pipeline
  and shaders aren't an environment change, but the merge gate for the branch runs it anyway.

## 8. Departures

- **From 0002 §8.4:** the swapchain is always `SDR` and the final pass always encodes (0002 said it encodes "when the
  swapchain isn't `SDR_LINEAR`"); the scene target is refitted to the acquired swapchain size each frame rather than
  on the pixel-size event.
- **From 0002.4 §4:** the mesh path and batch textures move to chunk 3, the blur chain to chunk 6 (§1).

## 9. Decisions

The user's, 2026-11-09, both as proposed:

1. **Move the mesh path and `Batch::texture` to chunk 3, and the blur chain to chunk 6**, each landing with its first
   user (§1).
2. **Always an `SDR` swapchain, encoded in the composite**, rather than `SDR_LINEAR` where available (§3):
   one tested path, and the UI blends the same on every machine.
