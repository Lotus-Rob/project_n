## 1. Why, and why first

Phase 6 needs a Chinese font, and upstream's Noto Sans SC is 8.3 MB a weight ([0002.4](0002.4-ui-and-text.md) §3);
painted art and full-window reference pictures will follow. The user's call (2026-11-09): **Git LFS**, set up and
verified **on its own branch, `git-lfs`, merged before phase 6's first** (`phase6-text`), so the game work starts on
a repository whose LFS already works on every machine and in CI.

## 2. Git LFS from Pixi, wired into git

Every tool comes from the Pixi environment (AGENTS.md), but LFS works through **git's own filters and hooks**, which
any git runs: the host's, the editor's, a container's. So the repository's local config points them at Pixi:

- **`git-lfs ==3.8.1`** in `pixi.toml` (conda-forge has it for linux-64, win-64 and osx-arm64), with its lock.
- **Filters** in the clone's `.git/config`, written by a new command (below):
  `filter.lfs.process = pixi run --quiet git-lfs filter-process` (one long-running process per git command, not one
  per file), `filter.lfs.clean` and `filter.lfs.smudge` likewise for tools that don't speak the process protocol, and
  `filter.lfs.required = true`, so a missing or failing `git-lfs` stops git instead of committing the raw file. Git
  runs filters from the repository's root, where `pixi run` finds `pixi.toml`.
- **The hook:** `.githooks/pre-push` (`exec pixi run --quiet git-lfs pre-push "$@"`) uploads LFS objects before a push,
  beside the existing commit hooks. `git lfs install` would also write `post-checkout`, `post-commit` and `post-merge`,
  which only manage lockable files' read-only flags; we lock nothing, so they're left out.
- **`project_n setup`** (new) replaces 0001 §5.1's manual step: it sets `core.hooksPath` and the filters (idempotent,
  local config only, never global), then runs `git lfs pull` to replace any pointer files a plain clone checked out.
  `doctor` reports a clone that needs it (missing config, or files `git lfs ls-files` marks as not downloaded) and
  says to run it.
- **A fresh clone** before `setup` has pointer files where LFS files belong; nothing else breaks, and `setup` fixes
  it. The README's first steps become `pixi install`, then `pixi run project_n setup`.

## 3. What is tracked

`.gitattributes` gains `filter=lfs diff=lfs merge=lfs -text` lines for:

- **Fonts:** `*.otf`, `*.ttf`.
- **PNGs** (§8, decision 1) under `assets/` and `tests/reference/`. Tracking a path that already holds
  plain blobs makes `git status` show them modified, so the same commit renormalises them (`git add --renormalize`):
  their next version is stored in LFS, about 3 MB of sprites and 6 MB of reference pictures today, and history keeps
  the old blobs (nothing is rewritten). Painted art and full-window pictures are where the size will come from.

`art/atlas.sha256` and the atlas step read the working tree's files, which the smudge filter has already restored,
so they're unaffected.

## 4. Checks

- **`lint`** runs `git lfs fsck --pointers` over the branch's commits: it fails on a file the attributes track but
  that was committed as a plain blob, or on a malformed pointer.
- **`artifact`** refuses to package a pointer file (a file under `assets/` starting with LFS's
  `version https://git-lfs.github.com/spec/v1` line), so a clone that skipped `setup` can't ship one.
- **`selftest`** covers `setup`'s config (written once, a second run changes nothing) and the pointer test.

## 5. CI

- **No LFS in `actions/checkout`:** its `lfs: true` uses the runner's preinstalled git-lfs (a host tool) and caches
  nothing, and the runners' own git-lfs would smudge files during the checkout, so every checkout runs with
  `GIT_LFS_SKIP_SMUDGE=1` and leaves pointers. Each job that builds or tests (lint, the three container jobs, windows, macos; not `release`, which only
  publishes archives already built) instead restores `.git/lfs/objects` from the Actions cache, keyed on a hash of
  `git lfs ls-files --long` (each tracked file's object ID, printed by `project_n lfs-key`, so no shell logic or
  `sha256sum` is needed on any runner), then runs `project_n setup`, which fetches what is missing.
- **On a miss** the newest older cache is restored (`restore-keys`), so only changed objects download; `project_n
  lfs-prune` then deletes the objects the checkout doesn't use (`git lfs prune` with its "recent" windows at zero),
  and the cache is saved under the new key holding exactly this commit's objects, so old versions never pile up.
- **One composite action,** `.github/actions/lfs/action.yml`, holds those steps, so the jobs share them.
- **Why the cache matters:** a personal account gets 10 GiB of LFS bandwidth a month, and Actions' downloads count
  against it (GitHub's Git LFS billing page). Uncached, every push would download every LFS file in each of six jobs;
  cached, a push downloads only objects that changed.

## 6. Containers

`check --container` mounts the working tree (`-v <root>:/src`), so the files LFS restored on the host are already
there. A git command inside the container reads the clone's `.git/config`, whose filters call `pixi run git-lfs`:
the image's Pixi environment comes from the same `pixi.toml`, so it has `git-lfs` too. `check --container` on this
branch verifies it.

## 7. Verification: what "done" means

The branch carries a real payload, **the font** (`assets/fonts/NotoSansSC-Regular.otf`, its OFL licence and
`assets/fonts/PROVENANCE.md` with source URL and SHA-256), which nothing loads until `phase6-text`:

1. A fresh clone followed by `setup` has the real font, byte for byte the recorded SHA-256.
2. `git cat-file -p HEAD:assets/fonts/NotoSansSC-Regular.otf` shows a pointer, not the font.
3. A commit from the host's git outside any Pixi shell (an editor's terminal) stores a pointer through the filter.
4. The push uploads the object (the pre-push hook), and GitHub shows the file as stored in LFS.
5. CI: every job pulls; the second run hits the cache and downloads nothing.
6. `check --container` passes; Windows and macOS CI jobs pull through the same action.
7. `lint`'s `git lfs fsck --pointers` fails on a tracked file committed as a plain blob (tried by hand in a scratch
   clone, not committed).

## 8. Decisions (the user, 2026-11-09)

1. **PNGs too:** `assets/**/*.png` and `tests/reference/*.png` are tracked from this branch on, renormalised in one
   commit (§3).
2. **`project_n setup`** is the one-time clone setup that `doctor` points to (§2).
3. **The font is this branch's payload** (§7), so LFS is verified on the file it was set up for.
