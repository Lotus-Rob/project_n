0002.3 settles what chunk 3 does. This document settles how: who owns what, the interfaces, the files, the tests and
the order of commits. Where it departs from 0002.3, §8 says so, and 0002.3 is updated with the code.

## 1. The job system moves to App

- `app::App` owns `core::Jobs`, a member built before the logic thread starts:
  `Jobs(DefaultWorkers(), /*externalThreads=*/1)`. The main thread becomes enkiTS's thread 0.
- `Jobs::ThreadRegistration`, an RAII guard, wraps enkiTS's `RegisterExternalTaskThread` and its deregistration;
  `App::RunLogic` holds one for its whole body, so an exception still deregisters.
- App sets the simulation's floating-point environment on the main thread: waiting on a `Pending`, it may run the
  logic's chunks. `Game`'s destructor waits for a save in progress, as the job system's shutdown used to.
- `Game` takes `core::Jobs&` (a constructor argument) instead of owning one; `Game`'s log line about workers moves to App.
- The forking rule: `ParallelFor`, `Background` and `WaitForBackground` may run on the creating thread or on a
  registered one (enkiTS numbers external threads 1 to N, workers after them, so the assert becomes
  `thread <= externalThreads`). `Background` stays the logic thread's (the
  save writer); nothing on the main thread uses it.
- **`Jobs::Start(chunks, body) → Pending`**: `body` is a `std::function<void(u32)>`, run once per chunk at low
  priority; `Start` returns at once. `Pending` owns the task: `Done()` polls (an acquire load, for TSan, as
  `BackgroundTask` does); its destructor waits. Main thread only, in practice (the renderer's decodes).
- A `ParallelFor` waits only on high priority, so a logic join never runs a decode. A wait on a `Pending` may run the
  logic's high-priority chunks meanwhile; chunks are the unit of determinism, so that is harmless.

## 2. The manifest

**Inputs.** `art/sprites.toml` as now; new **`art/scenes.toml`**: one table per scene in F2's order, each with a
`sprites` list of names:

```toml
[arena]
sprites = ["ground", "rock_large", "pine", "shrine", "fox", "cultivator", "orb_blue", "shadow", ...]
[stress]   # the arena's plus the crowd's and the NPCs'
[painted]
[cells]
```

`./dev atlas` refuses an unknown sprite name, an empty scene and a duplicate name.

**Outputs.**

- **`assets/manifest.yaml`** (generated, "don't edit" header):

  ```yaml
  page_size: 2048
  pages: 1
  mip_levels: 5
  sprites:            # in art/sprites.toml order: a sprite's index is its SpriteId
    - { name: ground, file: sprites/ground.png, page: 0, region: [16, 16, 1920, 1080], foot: [0, 0] }
  scenes:             # in art/scenes.toml order: a scene's index is its SceneId
    - { name: arena, sprites: [ground, rock_large, ...] }
  ```

- **`src/core/generated/atlas.hpp`** keeps only `enum class SpriteId` and `SPRITE_NAMES`
  (`std::array<std::string_view, N>`, indexed by `SpriteId`). `Sprite`, `SPRITES`, `PAGE_SIZE`, `PAGES` and
  `MIP_LEVELS` go.
- `art/atlas.sha256` also hashes `art/scenes.toml` and `assets/manifest.yaml`, so `lint` catches a stale or edited
  manifest as it does the header.

**`core/manifest.hpp`**, plain types:

```cpp
enum class SceneId : u16 {};               // a scene's index in the manifest
struct SpriteInfo { std::string file; u16 page, x, y, width, height, footX, footY; };
struct SceneInfo { std::string name; std::vector<atlas::SpriteId> sprites; };
struct Manifest {
    u32 pageSize, pages, mipLevels;
    std::vector<SpriteInfo> sprites;       // indexed by SpriteId; as many as SPRITE_NAMES
    std::vector<SceneInfo> scenes;         // indexed by SceneId
    const SpriteInfo& Sprite(atlas::SpriteId) const;
    const SceneInfo& Scene(SceneId) const;
    std::optional<SceneId> SceneNamed(std::string_view) const;
};
```

**`data/manifest.hpp`**: `ParseManifest(text)` and `LoadManifest(path) → std::expected<Manifest, core::Error>`, sharing
`data/internal/yaml.hpp` with the other readers. Errors carry the line, as the others do. It refuses: bad YAML, a
missing or mistyped field, a region outside its page or a page past `pages`, a foot outside its image, a scene naming
an unknown sprite, zero or more than 15 mip levels, and **a sprite list that differs from `SPRITE_NAMES`** (count,
order or a name): "the atlas is stale: `./dev atlas`".

**Who holds it.** `main` loads it right after finding `assets/` and fails to start without it. It becomes a
`std::shared_ptr<const core::Manifest>` in `app::Options`; App passes it to `Renderer::Create` and through `GameSetup`
to the arena.

**The twelve users of `core::atlas`'s metadata** (as built: the doc first counted eleven, missing the renderer's outline):

| User | Becomes |
|---|---|
| `core::MakeInstance(draw)` | `MakeInstance(const Manifest&, draw)` |
| `game::Arena`, `npcs.cpp` | hold the manifest (`std::shared_ptr<const Manifest>`), pass it to `MakeInstance` |
| `game::Look::Valid()` | `sprite < SPRITE_NAMES.size()` |
| `data::SpriteNamed` (the `shortcut:`) | `core::SpriteNamed` in `core/manifest.hpp` searches `SPRITE_NAMES`, for both readers; the shortcut goes |
| `gfx::BlockOf`, `WriteBlock` | take a `SpriteInfo` and the mip levels |
| `gfx` sprite array | sizes the texture, the sampler and the clears from the manifest |
| `gfx::Renderer`'s outline ring | the manifest's page size; the renderer keeps the manifest |
| `core::game_data.hpp`, `instances.hpp`, `components.hpp` | keep including the header for `SpriteId` only |

## 3. Scenes in the simulation

- `core::Simulation` gains **`virtual SceneId Scene() const = 0`**, the scene its state needs.
- `game::Arena(std::shared_ptr<const Manifest>, Scene, const GameData&)`. A table in `arena.cpp` names each
  `game::Scene` in the manifest: arena, stress, painted, cells. The arena resolves its SceneId when built or loaded.
  `main` checks at start that the manifest names every scene the table needs, else fails to start ("`./dev atlas`"),
  and that every scene lists the creatures' data-table sprites: a creature drawing a sprite its scene didn't load
  would be invisible. A hot reload naming such a sprite is refused the same way, with the old data kept.
- `game::SceneNamed(std::string_view) → std::optional<game::Scene>` and `game::SceneName(Scene)`, for `main`.
- **F2** (§12 decision 5): `Control::CycleScene` bound to F2, sending **`ActionKind::CycleScene`**, recorded in
  replays like Select. `Arena::Tick` taking it rebuilds the arena as the next scene in F2's order (arena → stress →
  painted → cells → arena): the constructor's body moves into `Build(Scene)`, which both call. The
  tick counters go on; the selection clears. The next burst finds a scene that isn't resident and waits for it.

## 4. The protocol in `core::Logic`

- `Snapshot` gains `SceneId scene`; `Action` gains `SceneId scene` (for `SceneResident`); `ActionKind` gains
  `CycleScene` and `SceneResident` (the last, so `ACTION_KINDS` stays the bound the replay reader checks).
- `Logic` holds **`std::optional<SceneId> m_resident`**, empty at the start.
- `RunBurst`: while `m_simulation->Scene() != m_resident`, the burst runs **`Wait()`** instead of ticks, once:
  - it takes live input only (never the replay's), and records nothing; no counter moves; no replay hash is checked;
  - Pause and Resume update the window's pausing (and the simulation's, unless a replay plays) as `TakeInput` does;
  - `SceneResident` sets `m_resident`; every other action is dropped with a debug line;
  - it returns a stall when the needed scene became resident, so the clock restarts; otherwise it ends the burst.
  The burst then publishes as usual, `advanced` false, naming `Scene()`.
- `TakeInput` on a running tick applies and strips any `SceneResident` before recording, so a replay never holds one;
  the replay reader refuses one, as it refuses Load and ReloadData.
- Phase 4's frozen-tick load stays as it is: it restores the state, and if the scene differs the next bursts wait.
  The same holds for a replay starting in another scene. The doc comment on `RunBurst` says so.

## 5. The renderer and App

- **`Renderer::Create(window, assets, manifest)`** creates the device, the pipelines and the texture array (every
  page, cleared to transparent) but loads no sprites. It keeps the assets path and the manifest.
- **`Renderer::Holds(SceneId) → bool`**: every sprite of the scene uploaded and the mips generated since.
- **`Renderer::BeginScene(SceneId, core::Jobs&)`**: for each of the scene's sprites not uploaded yet, a slot
  (`std::expected<Surface, Error>`); `Jobs::Start` decodes and premultiplies one sprite per chunk into its slot. Asserts
  that no other scene is loading.
- **`Renderer::ContinueScene(budgetNs) → std::expected<bool, core::Error>`**: nothing until the `Pending` is done;
  then uploads decoded sprites one at a time (a transfer buffer and a copy pass each, as now) until the budget is
  spent; once all are in, generates the mips for the array and returns true. A decode failure (a missing image, a
  wrong size: "run `./dev atlas`") is the error.
- `Draw` and `Capture` of a snapshot whose scene the renderer doesn't hold draw the clear colour only and upload no
  instances.
- **App** keeps `std::optional<SceneId> m_reported`. Each frame, before drawing, when the drawn snapshot's scene isn't
  `m_reported`: if the renderer doesn't hold it, it begins (once) and continues the load with a **2 ms budget**; when
  it holds it, App sends `SceneResident{ scene }`, sets `m_reported` and logs "scene X resident in N ms". A load error
  is logged as critical and `Run` returns 1, as a logic thread failure does.
- `main`'s flags come from the manifest: `--<name>` for every scene `game::SceneNamed` knows (`--stress`, `--painted`,
  `--cells` keep working); the hard-coded `ChooseScene` goes.

## 6. Testing

- `core_tests`: `Jobs::Start` runs every chunk and `Done()` turns true; a high-priority `ParallelFor` returns while a
  low-priority `Pending` is still blocked; a registered thread forks and joins. `MakeInstance` against a hand-built
  `Manifest`. `Logic`: a burst waiting for a scene counts no tick, records nothing, keeps Pause and drops other
  actions; the one taking `SceneResident` stalls; a `SceneResident` on a running tick isn't recorded. The fixtures
  report their scene resident when built.
- `data_tests`: the shipped `assets/manifest.yaml` parses and matches `SPRITE_NAMES`; each refusal of §2 is an error
  with its line.
- `gfx_tests`: `BlockOf` and `WriteBlock` with a hand-built `SpriteInfo`.
- `game_tests`: F2's cycle visits every scene in order and back; a replay with a scene change, a save, a load into
  another scene and a month step plays back with every hash matching (0002.3 §9's gate).
- Tests that build an arena (`game_tests`, `app_tests`, `headless_bench`, `fuzz_save`, `reference_tests`) load the
  shipped manifest through one helper, `tests/support/manifest.hpp` (`TestManifest()`: `data::LoadManifest` on
  `platform::AssetsDirectory()`, loaded once). Their targets gain `data`, `platform` and the `assets` rule.
- `reference_tests` load their scene through `BeginScene` and `ContinueScene` until it is held.
- `fuzz_yaml` gains the manifest reader and a seed.
- `tools/test_project_n.py`: the atlas step writes a manifest that names every sprite and scene; an unknown sprite in
  `scenes.toml` is refused.
- As built: `TestManifest()` reads the file on each call (a static would need an exit-time destructor); the
  `data_tests` target takes the manifest too, for the shipped-manifest test.

## 8. Departures from 0002.3

- **Names, not a hash.** The header lists the sprite names and `LoadManifest` compares the lists. It is as cheap
  and says which name differs. 0002.3 §6 proposed a hash of the names.
- **Uploads start once every decode is done**, not as each lands. Each sprite's upload still stays inside the 2 ms
  budget and the window never freezes. Per-slot readiness can come when scenes outgrow a second of decoding.
- **Sprites already uploaded aren't decoded again.** Scenes share page 0, so going back to a scene loads nothing.
- **`ReloadData` sent while a scene loads is dropped** with the rest. The edit is lost until the next one. This is a
  debug-only gap, logged at debug level.
