# Phase 6, chunk 5c1: the world kept, and saves as deltas — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The game's world is generated from the seed once per new game or load and outlives every scene change, and a
save holds only what differs from that regenerated base, loading to an identical, deterministic state.

**Architecture:** The world-side state (`core::State`, relationships, travel, calendar, pause, the cultivator's map
place) moves into a `game::WorldState`; `Host` keeps the game's one and, while a dev scene runs, a scratch one. Stable
IDs split into a world range and a scene range so the base world doesn't depend on scene history. A generic field-level
delta in `core` (driven by each type's existing `Fields()`) writes a domain against its base; journeys are written by
what defines them and their legs rebuilt from the map.

**Tech Stack:** C++23, EnTT, doctest, XMake through `pixi run project_n`; LZ4 (zstd only if Task 9 measures it worth it).

**Spec:** `docs/superpowers/specs/2026-11-16-phase6-chunk5c1-world-kept-delta-saves-design.md` (approved 2026-11-16).

**When:** after 5b2 merges (its Tasks 13 to 19 change `game/host.*`, `game/scenes/world.*` and remove the stand-in
walkers), on a branch `phase6-chunk5c1` from main. Names below are 5b2's as of "docs(agents): say which months the
world's build seeds travel for"; the pre-flight conflict scan checks each one against main before Task 1.

## Global Constraints

- **Exactness (the user's condition):** a load gives a state whose `StateHash` equals the saved one's, with every
  entity in the same order, and every tick, month step, journey and draw after it equals a run that never saved, on 1
  and 4 workers. Any difference is a failure, never a tolerance.
- **The game's world is built once** (new game, or a load's regeneration) and never rebuilt, respawned or re-seeded by
  a scene change. Game scenes (today `world`) run on it; dev scenes (`arena`, `stress`, `painted`, `cells`) run on a
  scratch world built on each entry as today, with its own calendar; the game's world is set aside untouched meanwhile.
- **Stable IDs:** world entities draw from the world counter (from 1); a scene's own entities from the scene range
  `SCENE_ID_BASE = 1ULL << 62`, its counter kept for the session and never reused. A world NPC moved into a scene keeps
  its world ID.
- **The base's identity:** seed + `GENERATOR_VERSION` (u32, starts at 1; raised whenever generation changes what it
  makes, `StartingPower` included) + `GameData::BaseHash()` (the world map and names only). A mismatch is refused,
  logged saying which.
- **One list of fields per type:** the delta compares through each type's `Fields()`; each argument of the `Fields()`
  call is one field (a vector is one field); no second field list anywhere.
- **`StateHash`** hashes the running world (game or scratch: domains, records, counters) and the scene, in the state's
  order as today (`Save` sorts canonically first); never the delta's bytes; the set-aside game world is not in it.
  `Host::WorldHash()` hashes the game world's part alone.
- **One save file** with sections (header, game world, scratch world when a dev scene runs, scene), through
  `core::WriteSaveFile`'s temporary-file-and-rename. Old saves are refused, never migrated.
- **The way back:** leaving the world scene by F2 keeps the cultivator's foot; leaving by a portal keeps the point it
  stood on the tick before it touched the portal's area (`Body::previous` on the tick `OnPortal()` fires).
- **Aims (Task 9 measures, the Outcome records; a miss reported with its reason):** a new game's save of the shipped
  world under 10 KB on disk; after three month steps at most a third of 1.84 MB; saving no slower than ~16 ms
  (release); a load, regeneration included, under 100 ms.
- src/AGENTS.md rules (sized types, `pch.hpp`, Doxygen on every public name, no `switch` over a whole enum,
  `PN_PROFILE_ZONE` on per-frame functions, log outcomes only); tests per tests/AGENTS.md (about 20 named samples, never
  sweeps; one worst value asserted once). Code comments never cite the design process.
- Each task updates the AGENTS.md lines its change makes untrue (src/AGENTS.md's world, save and scene lines;
  tests/AGENTS.md's fuzz seeds; design doc 0002 §7.6 in Task 7) in the same commit, and regenerates the `save` fuzz
  seeds (tests/AGENTS.md's two commands) when the layout moves.
- Gates: an edit round runs `pixi run project_n test --suite <s> [--test <t>]`; a task ends with
  `pixi run project_n test` and `pixi run project_n lint --range <task base>..HEAD`, plus `pixi run project_n reference`
  when names, scenes or what's drawn could move (Tasks 2, 6). A moved reference picture is looked at (look-at-the-game
  skill) before `--update`, and the reason goes in the commit body.

### Task 3: a field-level delta of a domain against its base

**review: full** (saves, untrusted input)

**Files:** Create `src/core/delta.hpp` (templates; a `delta.cpp` only if something isn't a template); Test
`tests/unit/core/delta_tests.cpp`; extend `tests/fuzz/save.cpp` only if it can reach the reader without a host
(else Task 8 covers it).

**Interfaces:**
- Produces (`core`, delta.hpp):
  - `template<typename Archive, typename... Components> void SaveDomainDelta(Archive& archive, const Domain& base,
    const Domain& now, ComponentList<Components...> components);`
  - `template<typename... Components> void LoadDomainDelta(Reader& archive, State& state, DomainIndex index,
    ComponentList<Components...> components);` (`state[index]` holds the regenerated base; applies the delta in place;
    fails `archive` and leaves the state for the caller to drop on any refusal)
  - `struct DeltaCounts { u64 removed = 0; u64 created = 0; u64 changed = 0; };` and
    `template<typename... Components> [[nodiscard]] DeltaCounts CountDelta(const Domain& base, const Domain& now,
    ComponentList<Components...> components);` (`changed`: entities with at least one changed field or component)
- Layout (decided here; byte coding left to the implementer): entities removed since the base (by their place in the
  base's stable-ID order), entities created (stable ID, then each component whole); then per component, in list order:
  base entities that gained it (whole), lost it, and changed it (place in base order + a u64 mask of changed fields);
  then, per field, every changed entity's new value, in entity order. A type with more than 64 fields fails to
  compile. A field's bytes are what `Writer` writes for it (one `Fields()` argument).
- Refusals: a base place past the base's count, a created ID the state already has or outside both ID ranges, a mask
  bit past the type's field count, a component gained by an entity that has it, a value that fails `Valid()`, a
  truncated section.

- [ ] **Step 1: Write the failing tests** (test components in the test file with 1, 3 and a vector field):
  `TEST_CASE("an unchanged domain's delta has no entries")` (`CountDelta` all zero; load gives the same hash);
  `TEST_CASE("a changed field is written once, and only it")` (one of three fields changed on two entities: the
  delta's bytes grow by the two values and their marks, not the other fields);
  `TEST_CASE("removed and created entities round-trip")`; `TEST_CASE("a component gained or lost round-trips")`;
  `TEST_CASE("a vector field changed in length round-trips")`;
  `TEST_CASE("the loaded domain hashes and iterates as the saved one")` (after `SortCanonical` on both);
  `TEST_CASE("a malformed delta is refused")` with one named sample per refusal above.
- [ ] **Step 2: Run** `pixi run project_n test --suite core_tests --test delta`: FAIL.
- [ ] **Step 3: Implement.** The field split: a `FieldBytes` archive that records each top-level `Fields()` argument's
  `Writer` bytes separately, so base and now compare field by field and a load patches the base's bytes and reads the
  component back through `Reader` (so `Valid()` and every read check apply).
- [ ] **Step 4: Run** `pixi run project_n test`: PASS.
- [ ] **Step 5: Commit** `feat(core): write a domain as its difference from a base`.
