# Roads Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Roads that are rerouted along the land, drawn as smooth ribbons with travellers on them, and chosen by
power: a weak traveller detours around danger sites, a strong one goes past.

**Architecture:**
- **core.** A `danger` tile feature (tiles within `danger_reach` of a danger site) and a per-profile added `danger`
  cost. Power bands in `TravelRules` map an NPC's power to a profile.
- **Journeys.** They carry that profile end to end: route, reach, plan and save.
- **Road shape in core.** It owns the roads' drawn centre lines (the rivers' centripetal Catmull-Rom spline, moved
  from gfx). gfx draws them as ribbons, and the game draws travellers on them.
- **Generator.** `art/world_map.py --roads` reroutes the roads over today's `world.yaml` and rewrites only its
  `roads:` and `fords:` blocks.

**Tech Stack:** C++23, XMake through `pixi run project_n`, doctest; Python 3 (Pixi's, no PyYAML) for the generator.

**Spec:** `docs/superpowers/specs/2026-11-22-roads-design.md`

## Global Constraints

- **Hashing.** `core::WALKING` (profile 0) stays `on_foot`, with no danger cost. It is what the player's
  `FindShortestRoute` and `MakePacedLeg` use, unchanged. Every new field of `WorldMapSource` and `TravelRules` is
  hashed by `WorldMap::Hash()`.
- **Danger tiles.** A tile carries `TileFlag::Danger` (16) when its centre is within `danger_reach` tiles (Euclidean:
  `dx*dx + dy*dy <= reach*reach`) of a `PlaceKind::Danger` place's tile. `danger_reach` is 0 to `MAX_DANGER_REACH`
  (16); 0, the default, marks none.
- **Danger cost.** A profile's `features.danger` is 0 to `MAX_WALK_COST` (default 0: no extra cost). It is added
  after the bridge, ford, river, road and kind rules. An impassable tile stays impassable, and the sum is capped at
  `MAX_WALK_COST`. The base layer (`m_cost`, `OnFoot`, used for reachability and regions) never takes it.
- **Bands.** `travel.bands` is a list of `{ from_power: <f32 >= 0>, profile: <key> }`:
  - The first `from_power` is 0, the list rises strictly, and each profile key exists.
  - Absent or empty means everyone walks `WALKING`.
  - Shipped: `[{ from_power: 0, profile: on_foot_wary }, { from_power: 5, profile: on_foot }]`.
- **Determinism and saves.** Simulation code is deterministic (src/AGENTS.md): maths through `core/math.hpp`, no
  clocks, the same result on 1 and 4 workers. Saves may break (before 1.0): bump `WORLD_VERSION` to 8 and regenerate
  the save fuzz seeds; no migration.
- **Drawn on the road.** It is presentation only: never saved, hashed or fed back to the simulation.
- **Code.** Sized types, `pch.hpp`, `///` on every public name; comments say why and never cite the design process
  (`lint` checks).
- **Tests.** About 20 samples per test (tests/AGENTS.md). Existing tests whose expected values change with the new
  roads are updated to the new values, never loosened or deleted.
- **Docs.** Each task updates the lines its change makes untrue, in the same commit. That includes the AGENTS.md
  files (src/, tests/, assets/, art/) and `world.yaml`'s and `world_look.yaml`'s comments.
- **Gates.** Edit rounds run `pixi run project_n test --suite <s> [--test <t>]`. Each task ends with
  `pixi run project_n test` and `pixi run project_n lint --range <task base>..HEAD`, plus
  `pixi run project_n selftest` for Python tasks.
- **Reference pictures.** `pixi run project_n reference` is red between Tasks 5 and 9 and is only viewed there. Task
  9 updates the pictures.

## Review Focus

1. **A traveller with NaN, negative or huge power:** `ProfileFor` gives the first band for NaN or a negative, and the
   last band for anything at or past the last `from_power`. It never indexes past the list. Task 3 tests it.
2. **A danger whose reach covers a city's tile, or every way into a city:** the wary profile still reaches the city
   (the cost is added, never impassable), and an NPC standing in reach can still set out. Task 1 tests the cost;
   Task 6 tests every band reaching every city on the shipped map.
3. **A save taken while a wary traveller is out and loaded:** the plan rebuilds the same journey by the same
   profile, and a plan naming a profile the map lacks is refused on load. Task 3 tests both.
4. **A walker stepping onto a road diagonally across the staircase corner, or off at a fork:** the drawn position
   moves no more than the simulated step plus 0.05 tile between ticks, with no jump. Task 8 tests it.
5. **`--roads` run twice, or on a file with comments inside `roads:`:** the second run changes nothing, and a
   comment line inside the rewritten blocks is refused with its line number rather than silently lost. Task 4
   tests both.

The rule, which the tests pin:
- Let the walker be between tile centres `a → b` of its leg, a fraction `t` of the way.
- Its road weight is `w = lerp(road(a), road(b), t)`, where `road(x)` is 1 for a `TileFlag::Road` tile and 0
  otherwise.
- It is drawn at `p + w·(nearest(p) − p)`, where `p = core::Where(...)` and `nearest` is the closest point on any
  road curve within 1.5 tiles (if none, `w = 0`).
- While standing, it uses its tile's `road()` value.

Held walking (no route) is drawn where it is: a free walk snapped onto a curve would slide against the input. The
controller lists this for the user.
