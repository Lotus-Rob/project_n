# Phase 6 chunk 5b2: moving on the world map, implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Days pass on the world map; world NPCs visit other cities along roads, weighed by pull, reach and city
character, recorded in a travel journal; the player clicks (or uses a target cursor) to walk routes; every NPC has a
generated name; a date line on the HUD shows the day and pauses the world; the stand-in walkers go.

**Architecture:** `core` gains movement profiles on `core::WorldMap`, distance maps and searches (`core/paths.*`) and
journeys of legs placed by pure functions of the world clock (`core/journey.*`), plus the names table
(`core/names.hpp`). `game` keeps the world clock, the journeys and the journal in the host (`game/travel.*`), decides
visits in the month step and publishes travellers in view from their records, as volleys are. `app` turns clicks, the
target cursor and the date line into actions; `gfx` draws the route line and the cursor's tile.

**Tech Stack:** C++23, EnTT through `core/ecs.hpp`, yaml-cpp behind `data`, SDL_GPU behind `gfx`, doctest, Python 3
(`art/`), XMake through `project_n`, all from Pixi.

**Status:** draft.

**Spec:** `docs/superpowers/specs/2026-11-15-phase6-chunk5b2-moving-design.md` (read it first: History, Goals,
Anti-goals, Calls). The 5b1 spec's Outcome describes the map this builds on.

## Global Constraints

- A day is 180 ticks (3 s at 60 Hz), a month 30 days (5,400 ticks); the world clock moves only in a scene showing the world map (`SceneTraits::worldMap`) and not paused.
- Cost is time: a step's ticks = its whole-number cost × its profile's `ticks_per_cost`. Shipped `on_foot` pace 16, so a
  road tile (cost 4) takes 64 ticks. Floats only to place a traveller between tile centres.
- Profile 0 is walking: every NPC journey and the player's routes use it in 5b2. A map built in code with no profiles gets
  one, `on_foot`, from its base costs at pace 16 (`core::DEFAULT_TICKS_PER_COST`).
- A leg is reached only through `core::Where(...)` and `core::EndTick(...)` (Task 7): nothing else reads a leg's tiles to
  place a traveller, so a new leg shape is one more case there.
- Nothing assumes one member per journey, one leg per journey or one profile.
- `world.yaml` and `names.yaml` are game data (hashed, read once at start, kept through the debug reload as the map is);
  `world_look.yaml` and `effects.yaml` are presentation.
- Names are never saved: `core::NameOf(names, seed, id)` is a pure function; 50,000 names never enter `core::Strings`.
- Determinism: `core/random.hpp` keyed draws, whole-number or fixed-point weights, fixed tie-breaks (lower tile index,
  lower city index, lower stable ID), parallel work merged in chunk order; the view rectangle never changes state.
- Saves: the host's format goes up once (Task 4: the clock and pause), the world version once (Task 9: travel, journal,
  `Action::Travel`); regenerate the `save` fuzz seeds with the commands in tests/AGENTS.md when the layout changes.
- `stress` and the arena keep their NPCs, grid and replay hashes (no starting power, no travel, no clock).
- src/AGENTS.md rules (sized types, `pch.hpp`, Doxygen on every public name, no `switch` over a whole enum,
  `PN_PROFILE_ZONE` on per-frame functions but not per-item ones, log outcomes only, no `std::sin` in simulation code);
  tests follow tests/AGENTS.md (about 20 named samples, never sweeps; one worst value asserted once).
- Each task updates the AGENTS.md lines its change makes untrue (root map's `assets/data/` list, src/AGENTS.md's world,
  rendering and command lines, tests/AGENTS.md's fuzz seeds) in the same commit.
- Gates: an edit round runs `pixi run project_n test --suite <s> [--test <t>]`; a task ends with
  `pixi run project_n test` and `pixi run project_n lint --range <task base>..HEAD`, plus `pixi run project_n reference`
  when it touches the atlas, publishing or drawing.

## Review Focus

1. A save made mid-journey (a traveller between tiles, one in its stay, the player on a route) loads to the same
   positions on the next frame, with no jump. Task 9 (travellers) and Task 14 (the player) add the tests.
2. A click on the cultivator's own tile, or a second click while a route is walking, replaces the route cleanly: no
   walk back to the old route's start, no zero-step leg that never ends. Task 14 adds the test.
3. A month step while the world is paused (M pressed) or while a route is walking: the clock jumps to the next month,
   travellers and the player continue from where the new tick puts them, and the pause holds. Task 4 and Task 14 add the
   tests.
4. A traveller whose home city's tile and destination share a tile run (a two-tile route), and a city unreachable by a
   profile: no division by zero, no journey to an unreachable city. Task 11 adds the test.
5. Leaving the world map mid-route (a portal, F2) and coming back: the route is gone, the clock stood still, travellers
   resume where they were. Task 14 adds the test.

## Rulings made while planning

- **Distance maps search backwards:** a map's cost at tile t is what walking from t to the goal costs, so the search
  from the goal relaxes a neighbour n by `StepCost(n, current, profile)` (the cost of stepping from n into current), not
  5b1's outward `StepCost(current, n)`, which suits regions only.
- **Routes from a map:** from a tile, step to the neighbour n with `StepCost(t, n) + Cost(n) == Cost(t)`, the lowest tile
  index on a tie; a back leg is the out leg's tiles reversed, its ticks recomputed (entering costs differ each way).
- **Legs own their tiles:** `core::Leg { shape, profile, startTick (i64), origin, tiles, arrive }`, `arrive[i]` the ticks
  from the leg's start to reach `tiles[i]` (u32); `origin` is the point the leg starts from (an NPC's first tile centre,
  the player's exact foot), so a route never makes its walker jump to a tile centre.
- **Ticks of journeys are signed** (`i64`), so Build can seed journeys that left before the clock's tick 0 (spec
  Goal 10) and a new game starts on month 1, day 1 with travellers already mid-road.
- **Stays drift between day points:** a stay's walker moves linearly from one point to the next each day, the points
  drawn per (journey seed, day) within 0.35 of a tile from the city's tile centre; continuous at every day boundary.
- **Group members** stand at fixed offsets from the leg's position (member 0 on it, the next ones 24 units apart on a
  small ring), so a convoy later needs no new placement.
- **The automatic month step** comes through a new `core::Simulation::MonthDue()`, which the logic checks after each
  ticked tick and treats as an `AdvanceCalendar` press (same transition, same frozen tick).
- **The clock while a month is due** stops (the ticks are frozen while the step is asked for, as today).
- **M (debug)** on a month not yet due moves the clock to the next month's first tick, then steps.
- **The world pause** is a host state flag (saved, hashed) toggled by a new `ActionKind::ToggleWorldPause`, ignored
  outside world-map scenes and cleared by a scene build; it is not the logic's focus pause, so the two never combine.
- **Travel rules are game data:** `world.yaml` gains `travel:` (share, stays, reach, the cultivator threshold) so
  tuning is a data edit and a measurement override goes through the data hash.
- **Weights in fixed point:** pull = destination people × 1,000,000 ÷ cost² (cost in profile cost units from the NPC's
  tile, at least 1); reach = max(0, R − cost) × 1,000 ÷ R with R = `reach_base` + power × `reach_per_power`
  (power truncated to whole numbers); character = the city's draw for the NPC's visitor kind; weight = the product, in
  u64, saturating.
- **Visitor kind:** cultivator at power ≥ `cultivator_power` (5), trader below.
- **Names:** a surname by weight, then one given character (30%) or two (70%), each uniform over `given`; the English
  form is `Surname Givenname` (the given pinyin joined, first letter capitalised), the Chinese form the characters run
  together.
- **Labels:** travellers carry `LabelPriority::Named`; a new `LabelPriority::Selected` sits between `Place` and
  `Player`, so the selected traveller's name always shows.
- **Placeholder look:** the route line is dots (`route_dot`) every 48 world units with `route_marker` on the
  destination; the cursor's tile is `target_tile`; all three new placeholder sprites in the world scene's list.
- **Controls:** pause the world: P, the gamepad's Back; the target cursor: T or the gamepad's Y to show and hide it,
  Enter or the gamepad's A to confirm, the movement keys, d-pad or left stick to step it (repeating every 0.15 s after
  0.3 s held).
