# Data-driven glows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Any sprite can wear a data-driven glow that follows its outline, read from a per-sprite distance field; the
swords, the bolt and the selection and hover outlines move onto it, and the arena shows every drive.

**Architecture:** Signed distance fields are computed per sprite on the job system as scenes load and kept in an R8
texture array beside the colour array (the atlas gutter grows to 32 texels so they fit). `effects.yaml` holds named
glows and maps each code-known role (`core::GlowRole`) to one; the renderer packs one GPU record per role. A sprite
instance carries its glow's inputs (role, value, start tick, result, element); the sprite shaders grow its quad, read
the field and evaluate the drive at the frame's time, statelessly. `core::GlowStrength` is the C++ statement of the
drive maths, unit-tested, mirrored in HLSL, and tied to it by a reference test that measures the drawn glow.

**Choices the spec left to the builder, made here:** drives are evaluated **in the shader**, not on the main thread (the
spec's recommendation): world instances are uploaded once a snapshot (60 Hz), so a CPU pass would step pulses at the
tick rate and scan up to 100,000 stress instances per snapshot, while the shader is smooth at any frame rate and is
already the GPU route; `GlowStrength` keeps the maths testable in C++. Roles map to glows only through `glow_roles:`
(the ability looks get no `glow:` field): one mapping, one place to check. The instance grows from 40 to 52 bytes.

**Tech Stack:** C++23, SDL_GPU, HLSL (compiled by `project_n shaders`), yaml-cpp (data module only), doctest, XMake
through `project_n`, Python standard library (`tools/project_n.py`).

**Spec:** `docs/superpowers/specs/2026-11-12-phase6-glow-design.md` (approved 2026-11-12). Read it with this plan.

## Global Constraints

- Glows are presentation: nothing in `core`'s simulation or `game`'s logic reads a glow's look; the logic thread never
  reads `effects.yaml`; hashed game data (`creatures.yaml`, `abilities.yaml`) never names a glow; a replay's state hash
  never changes with glows.
- Stateless: a glow's look at any moment is a function of its role's record, the instance's inputs and the frame's
  time. Nothing is kept between frames.
- Field reach: 16 texels (`core::FIELD_REACH_TEXELS`); fields are signed, negative inside, clamped to ±16, stored R8
  unorm with the edge at 0.5: `byte = round(255 × clamp(0.5 + d / 32, 0, 1))`.
- The atlas gutter is 32 texels between sprites and from the page's edges (`ATLAS_GUTTER`), each sprite owning 16 on
  each side; colour and field blocks are the region plus 16 texels each side.
- Colours are palette names (`<area>.<key>` of `core::UI_COLOUR_INFO`, such as `selection.selected`,
  `effects.damage`) or `element`; never hex.
- `pulse.period` is at least 1/3 s; `size` is above 0 and at most 16; `feather`, `opacity`, `zoom_shrink`, `depth` are
  0 to 1; `fade` above 0; at most 8 `results`.
- Reach at a zoom: `min(16, size × (1 / zoom)^zoom_shrink)`, in the sprite's texels.
- The user's shipped defaults (Decision 8), for `sword_aura` and `bolt_aura`: `colour: element, blend: light, size:
  8.5, feather: 0.75, opacity: 0.15, zoom_shrink: 0.6, drive: { kind: pulse, period: 1.6, depth: 0.9, curve: sine }`.
- Outlines (`selected`, `hover`): `blend: ink, size: 3, feather: 0, opacity: 1, zoom_shrink: 0, drive: steady`, colours
  `selection.selected` and `selection.hover`.
- Each sword's pulse starts at its own launch tick; the bolt's at its cast.
- `art/sprites.toml` is never reordered or shortened (stable IDs): `halo` and `glow_core` stay listed.
- Every task follows AGENTS.md (root, `src/`, `tests/`, `tools/`, `shaders/` where touched): sized types, Doxygen on
  public declarations, `pch.hpp` for standard headers, `PN_PROFILE_ZONE` in per-frame functions, no hex colours in code
  or shaders, `./dev shaders` and commit `shaders/bin/` and `src/gfx/generated/` after shader edits, `./dev atlas` and
  commit its outputs after atlas changes.
- Gates (AGENTS.md "Working with superpowers"): during a task only `pixi run project_n test --suite <s> [--test <t>]`;
  at a task's end and after its review fixes `pixi run project_n test` and `pixi run project_n lint --range
  <task base>..HEAD`; `pixi run project_n check` only at the branch head. A task that moves pixels also runs
  `pixi run project_n reference` and updates pictures only with a look and a reason.

## Review Focus

1. **A glowing sprite at the farthest zoom (0.25):** the reach clamps at 16 texels and never samples a neighbour's
   field; a pale halo of the neighbour must never appear. Test: Task 1's selftest (gutter) and Task 7's reference
   picture at zoom 0.25.
2. **A long session:** a start tick far from tick 0 (above 2³²) draws the same pulse phase as near tick 0. Test:
   Task 5's packing test on wraparound, Task 8's measured case at tick 2³² + 30.
3. **A reload of `effects.yaml` that breaks a glow** (unknown name, missing role, period 0.2): refused with its line,
   the old table stays and keeps drawing. Test: Task 4's loader tests.
4. **The selection outline on a dissolving or recoloured creature**, and a palette change: outlines follow the palette
   and ignore dissolve. Test: Task 9's reference cases (`outlines`, `recoloured`).
5. **Tuning a glow live** (debug data watch) while a volley flies: the next frame draws the new look, and the
   shipped table brings the old one back. Test: Task 10 extends "new effects change the next picture of the same
   snapshot, and the shipped ones bring it back" with a `sword_aura` of size 4.

  the field of the image's alpha (≥ 128 inside), for the block of `(width + 32) × (height + 32)` texels, rows without

  `(-16) == 0`, `(16) == 255`, `(40) == 255` (clamp), `(1.5) == 140`. A 1×1 opaque image: the texel itself encodes

  opaque square: its centre texels encode −1.5, edge texels −0.5. A 5×5 ring with a transparent centre texel: the
  centre encodes +0.5. A fully transparent 3×3 image: every texel encodes 255. A diagonal half (alpha where x ≥ y,

  measures).
