# Phase 6 chunk 5b1: the world map as data, implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The world scene shows a hand-made, organic world map read from `assets/data/world.yaml` (terrain, roads,
rivers, cities and danger sites, walk costs), drawn by the renderer from that map and `world_look.yaml`, with place
names from data and the 50,000 world NPCs living in its cities and regions.

**Architecture:** `core::WorldMap` holds the authored map and the layers derived from it (kind, flags, cost, place and
region per tile), built by a pure `core` function from what the `data` reader parsed; it hangs off `core::GameData`
behind a `shared_ptr` and is hashed with it. Presentation (`core::WorldLook`, from `world_look.yaml`) never reaches the
logic: `gfx` draws the static map itself (a pure `gfx::DrawTerrain` into instances, uploaded only when the tiles in view
or the look change) under the snapshot's ground. Strings gain entries named by data, so place names need no code.

**Tech Stack:** C++23, EnTT through `core/ecs.hpp`, yaml-cpp behind `data`, SDL_GPU behind `gfx`, doctest, Python 3
(`art/`), XMake through `project_n`, all from Pixi.

**Spec:** `docs/superpowers/specs/2026-11-15-phase6-chunk5b1-map-design.md` (read it first: History, Goals, Anti-goals,
Calls). 5a's spec Outcome (`2026-11-14-phase6-chunk5a-measure-camera-design.md`) describes the world scene this replaces.

## Global Constraints

- `world.yaml` is game data (hashed: a replay recorded on one map refuses another); `world_look.yaml` is presentation
  (never hashed, saved or seen by `game`; reloaded live by debug builds, the old table kept on an error).
- The map stays out of the debug data reload: a reload keeps the loaded `GameData::world` pointer; a `world.yaml` edit
  shows after a restart.
- Map size 150 × 85 tiles of 256 units (`WORLD_COLUMNS`, `WORLD_ROWS`, `WORLD_MAP` stay in code); `WORLD_BUSIEST`
  (33,000, 10,800) lies in the port's tile. Both pinned by tests that say why (the stand-ins' checks, `measure`'s path).
- Walk costs are whole numbers; impassable is `core::IMPASSABLE_COST`. Shipped values: road 4, meadow 10, grassland 10,
  sand 14, forest 16, hills 20, marsh 25, shallows 30, snow 30, rock 40, ford 30, deep water and peaks impassable.
- A map change (moving a city, a road, a coast; adding or renaming a place) needs no code change, sprites aside.
- No new dependency (spec, "Libraries checked"); our own search, rasterisation and noise.
- `stress` and the arena keep their world NPCs, grid (`npc % WORLD_CELLS`) and replay hashes; their reference pictures
  don't change.
- No `-ffp-contract` flag (spec Goal 10); simulation code stays deterministic (`core/math.hpp`, `core/random.hpp`, fixed
  tie-breaks, no floats in derived layers).
- src/AGENTS.md rules (sized types, `pch.hpp`, Doxygen, no `switch` over a whole enum, `PN_PROFILE_ZONE` on per-frame
  functions, log outcomes only); tests follow tests/AGENTS.md (~20 named samples, never sweeps).
- Each task updates the AGENTS.md lines its change makes untrue (root map's `assets/data/` and `art/` lists, src/AGENTS.md's
  world and rendering lines) in the same commit.
- Gates: an edit round runs `pixi run project_n test --suite <s> [--test <t>]`; a task ends with
  `pixi run project_n test` and `pixi run project_n lint --range <task base>..HEAD`, plus `pixi run project_n reference`
  when it touches the atlas, publishing or drawing.

## Review Focus

1. A `world.yaml` saved with Windows line endings, a trailing space or a tab in a grid row: read as the same grid, or
   refused naming the line, never misread as a ragged or shifted map. Task 5 adds the test.
2. A place name present in `strings.yaml` in one language only: refused at start-up like any string missing a language.
   Task 2 adds the test.
3. A `world_look.yaml` reload that drops a kind the map uses or names a sprite the atlas lacks: logged, the old look keeps
   drawing. Task 7 adds the test.
4. The camera panned past the map's edge or zoomed out beyond it: the terrain draws only tiles on the map, never reads
   past the grid, and draws nothing for a view wholly off it. Task 9 adds the test.
5. A save from the arena or `stress` (world NPCs with no home) still loads; a world save whose NPC names a home past the
   map's cities refuses. Task 11 adds the tests.

## Rulings made while planning

- **Strings by key:** `core::StringId` becomes `u16`; values from `core::STRINGS` on name entries of `strings.yaml` no
  code names ("data strings"), in file order. `core::Strings::text` becomes a vector (named first), with `keys` for the
  data strings and `Find(key)`. An unknown top-level key is no longer a warning: it is a data string (a typo of a named
  one is still refused, as that one is then missing).
- **Place names render as a new text kind,** `core::TextKind::Place`, at `gfx::PLACE_WORLD_SIZE` 72 world units (18 px
  at zoom 0.25 on 1080p, so names read at the widest view where creature labels have faded), through the label pass
  (fading, declutter) with `core::LabelPriority::Place` between `Named` and `Player`.
- **Step costs** (one rule for regions now and paths in 5b2), `WorldMap::StepCost(from, to)`: orthogonal = the entered
  tile's cost; diagonal = cost × 7 / 5 (integer), allowed only when both orthogonal neighbours are passable.
- **Rasterising** a polyline marks every tile each segment passes through, stepping one axis at a time (4-connected),
  so road and river tiles always touch edge to edge.
- **Overlays by neighbour mask:** a road or river tile draws one of 16 sprites by which of its N, E, S, W neighbours
  carry the same line (bits 1, 2, 4, 8); a bridge (road over river) draws the river, the road, then `bridge_h` or
  `bridge_v` by the road's direction; a ford draws `ford` over the river. Markers are flat icons on the ground.
- **Danger sorts are data strings,** not an enum: the look must give a marker for each sort the map uses. Shipped sorts:
  `haunted_forest`, `mountain_pass`, `shrine`, `cave`, `cliff`, `corrupt_village`.
- **The portal follows the start:** a scene hook `Scene::Portal(const SceneContext&)`, `Traits().portal` by default;
  the world's is the start city's tile centre plus (−560, −200), today's offset.
- **Stand-in gatherings from the map at build:** the busiest round the port (the city whose tile holds `WORLD_BUSIEST`),
  the three towns round the first three other cities in place order (the start excluded); 5a's compile-time checks
  (on the map, clear of the start, apart) become tests on the shipped map. A spread walker whose centre lands on an
  impassable tile redraws with the next draw index, up to 16 times, else is left out.
- **NPC homes:** 70% of a city's share on its own tile, the rest on its region's passable tiles by a draw keyed on the
  NPC's index; `Npc::home` is a `u16` city index, `game::NO_HOME` (0xFFFF) for scenes without a map.
