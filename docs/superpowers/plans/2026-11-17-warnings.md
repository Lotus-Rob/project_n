# Warnings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Drop GCC's `-Weffc++`, relax three MSVC warnings and the magic-number checks in tests only, remove unity
builds, and add per-task release builds to the gates.

**Architecture:** Build configuration (xmake.lua, tests/xmake.lua, a nested `tests/.clang-tidy`), the `project_n`
tool (tools/project_n.py and its self-tests) and the agent docs. No game behaviour changes.

**Tech Stack:** XMake 3.1, GCC / Clang / MSVC (msvc-wine), clang-tidy, Python 3 (project_n.py), doctest.

**Spec:** `docs/superpowers/specs/2026-11-17-warnings-design.md`

## Global Constraints

- The root `.clang-tidy` and `.clangd` stay untouched (the user's).
- Keep conversion warnings (C4242, C4267, `-Wconversion`), `bugprone-*`, sanitizers and `-Werror`; `src/` keeps every
  warning.
- Every suppression says why: a nested `.clang-tidy` has a `#` comment, each `/wd` flag a comment (`lint` checks the
  first).
- Existing test code is not rewritten to use the new freedoms.
- Code comments explain why in their own words, never cite specs, plans or design docs (`lint`'s
  `design_references`).
- Commits: Conventional Commits, scopes from `SCOPES` in tools/project_n.py (`xmake`, `tests`, `tools`, `agents`,
  `design`, `core`, ...); no `feat`/`fix` (no game behaviour changes).
- Each task ends with `pixi run project_n test` and `pixi run project_n lint --range <task base>..HEAD`; the
  controller then runs `pixi run project_n build --preset linux-gcc --mode release` and `pixi run project_n build
  --preset windows-msvc --mode release` in the main checkout.

## Review Focus

- A `{}` removed where it really initialised (a scalar or an aggregate of scalars inside a `NOLINTBEGIN` block): the
  member is then left uninitialised. Only `{}` that clang-tidy's `readability-redundant-member-init` calls redundant
  goes; Task 1's lint run is the check.
- `-Wno-effc++` placed where XMake emits it before `-Weffc++`, so GCC still warns: Task 1's failing-first GCC release
  build pins it.
- The MSVC `/wd` flags reaching `src/` objects (the module targets) rather than test targets only: Task 2 adds them in
  the test targets' definitions only.
- `tests/.clang-tidy` replacing rather than extending the root's checks (a missing `InheritParentConfig: true`
  silently drops every other check for tests): Task 2's step proves another check still fires.
- A `check` or `clean --stale` path still passing `unity` after the parameter is gone (a `getattr(..., "unity",
  False)` left behind): Task 3's selftest run and a grep for `unity` pin it.

- [ ] **Step 1: Remove the pairs in `src/core/journey.hpp` only, without the flag**

Delete each `// NOLINTNEXTLINE(readability-redundant-member-init): GCC's -Weffc++ requires an initializer` line and

- [ ] **Step 2: Build GCC release and see it fail**

Run: `pixi run project_n build --preset linux-gcc --mode release`
Expected: FAIL with `-Werror=effc++` ("should be initialized in the member initialization list") naming a journey
member. If it passes, find a header whose struct is default-initialised (`Trip trip;`) and repeat step 1 there.

- [ ] **Step 3: Add `-Wno-effc++` for GCC in xmake.lua**

In the `pixi-gcc` branch, with a why comment: `-Weffc++` comes with `set_warnings("everything")`; its useful items are
covered by `cppcoreguidelines-*` and Clang's `-Weverything`, and its member-initialiser item demands `{}` that
clang-tidy calls redundant.

- [ ] **Step 4: Build GCC release and see it pass**

Run: `pixi run project_n build --preset linux-gcc --mode release`
Expected: build ok. If it still fails on effc++, the flag lands before `-Weffc++` on the command line: add it where
XMake emits it later (`add_cxxflags` vs `add_cxflags`, or `{force = true}`) and check with
`build/compile_commands.json` from a linux-gcc build.

- [ ] **Step 5: Remove every other pair**

`NOLINTNEXTLINE` lines go with their member's `{}`. In `NOLINTBEGIN`/`NOLINTEND` blocks, remove both markers and the
`{}` of each member whose type has a default constructor that initialises it (standard containers, smart pointers,
`std::optional`, EnTT's registry, `core::Mutex`, our structs with member initialisers); keep `{}` on scalars and on
aggregates of scalars (that `{}` initialises). Leave `= std::nullopt` and other initialisers alone.

- [ ] **Step 6: Lint and test**

Run: `pixi run project_n lint --range <task base>..HEAD` (after committing, or on the working tree with `lint`) and
`pixi run project_n test`
Expected: no `readability-redundant-member-init` finding, no `cppcoreguidelines-pro-type-member-init` finding, all
tests pass. A `pro-type-member-init` finding means a `{}` that initialised went: put it back.

- [ ] **Step 7: Docs**

src/AGENTS.md: delete the effc++ gotcha. Doc 0001 rule 15: GCC's set is `-Wall -Wextra -Wpedantic` (`-Weffc++` off,
with the reason from step 3 and "the user, 2026-11-17, after 5b1 and 5b2"); Revised line: "2026-11-17, GCC without
`-Weffc++` (rule 15)".

- [ ] **Step 8: Commit**

```bash

git commit -m "build(xmake): drop GCC's -Weffc++ and the initialisers it forced"
```

- [ ] **Step 5: Prove the nested config only removes those checks**

`pixi run project_n lint`.

`unused_Name`. Remove the lines.

- [ ] **Step 6: tests/AGENTS.md**
